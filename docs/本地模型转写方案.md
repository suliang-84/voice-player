# 本地模型转写对接指南

本文说明：模型部署在**另一台电脑（GPU 机器）**上时，主后端（`voice-player-backend`）如何调用它完成语音转写。适合两类读者：

- **GPU 机器一侧**：负责部署模型、提供推理服务，关注第四章（接口规范）和第六章（实现指引）。
- **主后端一侧**：负责接入，关注第五章（后端配置与行为）和第七章（联调步骤）。

> **当前状态：** 本文是对接约定的草稿。接口规范（第四章）是我们自己定的契约，推理服务和主后端的 `RemoteAsrProvider` 都**尚未实现**。
> 文中涉及各模型的调用方式（接口、参数、单段长度上限等）没有对照官方模型卡核实，落地前需逐项确认。

## 一、对接方式总览

不要让主后端直接去加载或调用另一台电脑上的模型，而是在 GPU 机器上提供一个**推理服务**，主后端通过 HTTP 调用它。

```
主后端（voice-player-backend）                      GPU 机器
┌────────────────────────────┐   HTTP + token   ┌──────────────────────────────┐
│ Pipeline                   │ ───────────────▶ │ 推理服务（FastAPI）            │
│  └ RemoteAsrProvider       │  ① 上传声道音频   │  VAD → Qwen3-ASR → 对齐       │
│     （实现 AsrProvider）    │  ② 轮询进度       │  → CAM++ → SenseVoice        │
│                            │ ◀─────────────── │  任务队列 + 单个 GPU 工作线程   │
└────────────────────────────┘  ③ 取 JSON 结果   └──────────────────────────────┘
```

**这样分的原因：**

- 整条处理链（切段、转写、对齐、说话人、情感）前后依赖，放在同一台机器里，不用把中间结果来回传。
- 主后端保持轻量，只负责存储、任务状态和对外接口，不需要安装 torch 和各种模型依赖。
- 主后端的转写本来就藏在 `AsrProvider` 接口后面，新增一个 `RemoteAsrProvider` 并设置 `ASR_PROVIDER=remote` 即可，`Pipeline` 的流程、进度、失败重试都不用改。

**调用粒度：** 一次请求处理**一个声道**的单声道 WAV（与现有按声道转写的方式一致）。双声道音频由主后端拆成 A、B 两个文件，分别提交。

## 二、对接前准备清单

对接前，两侧各自确认：

**GPU 机器**

- [ ] 模型已下载到本地，能在本机用脚本跑通一段音频。
- [ ] 显存满足要求（Qwen3-ASR-1.7B 加 ForcedAligner 大约 8–10GB，需实测）。
- [ ] 服务监听 `0.0.0.0`（而不是 `127.0.0.1`），防火墙放行服务端口。
- [ ] 已生成访问令牌（token）。

**主后端机器**

- [ ] 能访问 GPU 机器的 IP 和端口（`curl http://<ip>:<port>/health`）。
- [ ] 如果本机配置了 `HTTP_PROXY` / `HTTPS_PROXY`，已把 GPU 机器的地址加入 `NO_PROXY`，否则内网请求会被代理拦截（常见现象是返回 502）。
- [ ] 准备一个测试用的单声道 WAV，例如 `voice-player-backend/data/cache/audio_003/track_A.wav`。

## 三、数据约定

**音频格式：** 单声道 WAV，16kHz，PCM16。8kHz 的电话录音由推理服务内部重采样。想省带宽可以上传 FLAC（无损，体积约减半），推理服务需同时支持。

**体积参考：** 21 分钟、16kHz 的单声道 WAV 约 40MB，局域网内直接上传即可。

**时间基准：** 所有时间戳以**整条音频开头为 0**，单位秒，保留三位小数。推理服务内部按段处理时，必须把每段起点的偏移加回去。

## 四、推理服务接口规范

采用「提交任务 + 轮询」，不用一个长请求等结果：21 分钟的音频要转写数分钟，长连接容易被代理超时断开。

**鉴权：** 除 `/health` 外，所有请求带请求头 `Authorization: Bearer <token>`。

### 4.1 接口一览

| 接口 | 作用 |
|---|---|
| `GET /health` | 各模型的加载状态，不需要鉴权 |
| `POST /v1/jobs` | 上传一个声道的音频，创建转写任务 |
| `GET /v1/jobs/{jobId}` | 查询状态和进度 |
| `GET /v1/jobs/{jobId}/result` | 任务完成后取结果 |
| `DELETE /v1/jobs/{jobId}` | 取消任务并清理 |

### 4.2 `GET /health`

```json
{
  "status": "ready",
  "models": {
    "asr": "ready",
    "aligner": "ready",
    "vad": "ready",
    "speaker": "ready",
    "emotion": "ready"
  },
  "queue": { "running": 1, "waiting": 2 },
  "schemaVersion": 1
}
```

`status` 取值：`loading`（有模型还在加载）、`ready`（可接收任务）、`failed`（加载失败，同时返回 `error` 字段说明原因）。

### 4.3 `POST /v1/jobs`

请求：`multipart/form-data`。

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 单声道音频文件 |
| `language` | 否 | 语种提示，如 `zh`、`en`；不传则自动识别 |
| `options` | 否 | JSON 字符串，开关各阶段：`{"align":true,"speaker":true,"emotion":true,"includeEmbedding":false}`，默认前三项为 `true` |
| `sha256` | 否 | 文件内容哈希，用于去重 |

响应：

| 状态码 | 含义 |
|---|---|
| `202` | 已创建，返回 `{"jobId": "...", "status": "queued"}` |
| `200` | `sha256` 命中已有任务，直接返回已有的 `jobId` |
| `400` | 音频无法解析 |
| `401` | token 无效 |
| `413` | 文件超过大小限制 |
| `429` | 队列已满，带 `Retry-After` 头（秒），调用方等待后重试 |
| `503` | 模型仍在加载，带 `Retry-After` 头 |

### 4.4 `GET /v1/jobs/{jobId}`

```json
{
  "jobId": "job_9f3a",
  "status": "processing",
  "progress": 0.42,
  "stage": "asr",
  "error": null
}
```

- `status`：`queued`、`processing`、`completed`、`failed`、`cancelled`。
- `progress`：0 到 1，单调不减。
- `stage`：当前阶段，`vad`、`asr`、`align`、`speaker`、`emotion`，便于排查卡在哪一步。
- 任务不存在或结果已过期返回 `404`。

### 4.5 `GET /v1/jobs/{jobId}/result`

仅在 `status=completed` 时可取，否则返回 `409`。

```json
{
  "schemaVersion": 1,
  "jobId": "job_9f3a",
  "language": "en-US",
  "duration": 1272.64,
  "segments": [
    {
      "start": 0.52,
      "end": 3.10,
      "text": "Okay, let's get started.",
      "confidence": 0.91,
      "speaker": "spk0",
      "emotion": "neutral",
      "events": ["Speech"]
    }
  ],
  "speakers": [
    { "label": "spk0", "embedding": [0.012, -0.034, "... 共 192 个浮点数"] }
  ],
  "models": {
    "asr": "Qwen3-ASR-1.7B",
    "aligner": "ForcedAligner",
    "vad": "FSMN-VAD",
    "speaker": "CAM++",
    "emotion": "SenseVoiceSmall"
  }
}
```

**字段说明：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `language` | String | BCP 47 语种，如 `zh-CN`、`en-US` |
| `segments[].start` / `end` | Number | 句级起止时间（秒），`end` 大于 `start`，按 `start` 升序 |
| `segments[].text` | String | 句子文本 |
| `segments[].confidence` | Number | 0 到 1，可选 |
| `segments[].speaker` | String | 声道内的匿名说话人标签，如 `spk0`、`spk1`，可选 |
| `segments[].emotion` | String | 情感标签，如 `neutral`、`happy`、`sad`、`angry`，可选 |
| `segments[].events` | Array | 声音事件，如 `Laughter`、`Cough`、`Breath`、`BGM`，可选 |
| `speakers[].embedding` | Array | 该说话人的平均声纹，192 维，可选 |

所有「可选」字段在对应阶段关闭或失败时**直接省略**，调用方必须容忍缺失。逐段声纹向量体积较大，默认不返回，需要时用 `options.includeEmbedding` 打开。

### 4.6 错误格式

非 2xx 响应统一返回：

```json
{ "error": { "code": "audio_invalid", "message": "无法解析音频文件" } }
```

### 4.7 数据保留

- 音频文件在任务结束（完成、失败或取消）后立即删除。
- 任务结果默认保留 24 小时，之后删除，再查询返回 `404`。
- 日志里不得输出音频内容和转写文本。

## 五、主后端侧：配置与行为

### 5.1 配置项（待实现）

在 `.env` 中配置：

| 配置 | 说明 | 示例 |
|---|---|---|
| `ASR_PROVIDER` | 设为 `remote` 启用远程转写 | `remote` |
| `ASR_REMOTE_URL` | 推理服务地址 | `http://192.168.1.50:9000` |
| `ASR_REMOTE_TOKEN` | 访问令牌 | `...` |
| `ASR_REMOTE_CONNECT_TIMEOUT` | 连接超时（秒） | `5` |
| `ASR_REMOTE_UPLOAD_TIMEOUT` | 上传超时（秒） | `300` |
| `ASR_REMOTE_POLL_INTERVAL` | 轮询间隔（秒） | `2` |
| `ASR_REMOTE_JOB_TIMEOUT` | 单个任务总超时（秒） | `3600` |

### 5.2 `RemoteAsrProvider` 需要实现的接口

`Pipeline` 已经按下面的约定使用转写引擎，`RemoteAsrProvider` 照此实现即可：

| 方法 / 属性 | 行为 |
|---|---|
| `transcribe(path, on_progress)` | 上传文件，每隔轮询间隔查询一次进度并回调 `on_progress(0~1)`，完成后取结果，转成 `Segment` 列表，返回 `(语种, 片段)` |
| `state` | `idle` / `loading` / `ready` / `failed`，由 `/health` 映射，结果缓存几秒避免频繁请求 |
| `error` | 失败原因，网络不通时为「无法连接推理服务」 |
| `start_preload()` | 重新检查 `/health`（模型加载失败后冷却期结束会调用） |
| `wait_ready(timeout)` | 轮询 `/health` 直到就绪或超时，超时抛出 `AsrUnavailable` |

**与现有逻辑的衔接：**

- 推理服务不可达、返回 `503`（模型加载中）或 `failed`，一律抛出 `AsrUnavailable`，现有流水线会把任务标记为「转写引擎不可用」，引擎恢复后下次访问自动重试，不会卡死。
- 收到 `429`（队列满）时，按 `Retry-After` 等待后重试，不当作失败。
- 单次请求的网络错误（连接中断、读超时）重试 2 到 3 次，带退避间隔。
- 提交时带上文件的 `sha256`，重试或重启后重新提交同一文件不会重复推理。

### 5.3 结果如何落库

- `Segment` 增加可选字段 `speaker`、`emotion`、`events`，旧 provider 不填即可。
- 转写表 `Transcript` 新增 `speaker_label`、`emotion`、`events`；新增声纹表，存 `audio_id`、`track_id`、`speaker_label` 和 192 维向量。
- `/transcripts` 每条多返回 `speaker`、`emotion`、`events`；`/speakers` 的 `emotionDistribution`、`sentimentScore` 改由情感标签汇总。
- 所有新增字段只增不改，已有的接口契约不变。

### 5.4 串音过滤

按声道转写时，对方的声音串进来会被转成「幽灵文字」（多麦克风录音很常见）。这个问题模型解决不了，在主后端 `pipeline._run` 里两路合并之后处理：对每个片段比较它在本声道和另一声道的音量，另一声道明显更响且置信度低的，丢弃或标记。可复用静音检测里已有的逐帧 RMS（`audio.frame_rms`）。

## 六、推理服务实现指引（GPU 机器侧）

### 6.1 服务骨架

- 用 FastAPI 提供第四章的接口，用 uvicorn 启动，监听 `0.0.0.0`。
- 模型在服务启动时后台线程预加载；加载期间 `/health` 返回 `loading`，`POST /v1/jobs` 返回 `503`。
- 任务队列加**单个** GPU 工作线程，一次只跑一个任务；队列满时返回 `429`。多个模型不要并行推理，避免显存溢出。
- 中间文件和音频放临时目录，任务结束后清理。

### 6.2 单个任务的处理流程

```
声道 WAV
  → ① FSMN-VAD：切出语音段，合并间隔小于 0.3s 的相邻段，单段限长
  → ② Qwen3-ASR：逐段转写，得到文本和语种
  → ③ ForcedAligner：把文本对齐回音频，得到字/词级时间，再按标点和停顿合成句级 start / end
  → ④ CAM++：每段取 192 维声纹，声道内聚类，标匿名说话人
  → ⑤ SenseVoiceSmall：逐段取情感、声音事件、语种标签
```

进度按阶段分配，大致 VAD 5%、ASR 50%、对齐 20%、说话人 10%、情感 10%，其余留给收尾。

**失败降级：** 对齐、说话人、情感任何一步失败，只丢掉对应字段，任务仍然完成并返回结果；只有 VAD 或 ASR 失败才把任务标记为 `failed`。

### 6.3 各阶段要点

| 阶段 | 要点 |
|---|---|
| VAD | 输出语音段列表；长音频必须分段，后续各阶段都按段处理 |
| ASR | 批量推理；段长要控制在模型能处理的范围内（Qwen3-ASR 的单段上限需查模型卡） |
| 对齐 | 时间要加回该段起点的偏移；对齐失败的段退回用 VAD 段边界 |
| 说话人 | 声道内凝聚聚类，用阈值决定说话人数；每个说话人保存平均声纹。CAM++ 官方模型偏中文，英文录音效果需实测 |
| 情感 | 咳嗽、呼吸、笑声等事件可用于过滤杂音；情感标签按说话人汇总 |

### 6.4 如果那台电脑上已有现成服务

如果模型已经有 HTTP 接口（例如用 FunASR 自带的服务，或用 vLLM 之类的框架起了服务），就不必再写完整的推理服务，只写一个**适配层**：把第四章的接口翻译成它现有的调用，并把它的输出转成 4.5 的结果格式。需要先看一下它现在的调用方式。

## 七、联调步骤

按下面的顺序逐步验证，每一步通过再做下一步，出问题时容易定位。

**第 1 步：GPU 机器本机验证服务**

```bash
curl http://localhost:9000/health
```

期望返回 `status: ready`。如果是 `loading`，等模型加载完。

**第 2 步：从主后端机器验证网络**

```bash
curl http://<GPU机器IP>:9000/health
```

不通时见第八章排错。如果本机有代理，加 `--noproxy '*'`。

**第 3 步：提交一个任务**

```bash
curl -H "Authorization: Bearer $TOKEN" \
     -F file=@track_A.wav \
     http://<GPU机器IP>:9000/v1/jobs
```

期望返回 `202` 和 `jobId`。

**第 4 步：轮询进度**

```bash
curl -H "Authorization: Bearer $TOKEN" http://<GPU机器IP>:9000/v1/jobs/<jobId>
```

重复执行，确认 `progress` 递增，`stage` 依次变化，最后 `status` 变为 `completed`。

**第 5 步：取结果并核对**

```bash
curl -H "Authorization: Bearer $TOKEN" http://<GPU机器IP>:9000/v1/jobs/<jobId>/result
```

核对：

- `segments` 按 `start` 升序，所有时间都在 `duration` 以内。
- 随机抽几句，用播放器拖到对应时间，确认文字和声音对得上（尤其检查是否漏加了段偏移）。
- 可选字段缺失时没有报错，只是省略。

**第 6 步：主后端端到端**

1. 配置 `ASR_PROVIDER=remote`、`ASR_REMOTE_URL`、`ASR_REMOTE_TOKEN`，重启主后端。
2. 访问 `GET /api/v1/audios/audio_003/transcripts`。转写未完成时返回错误码 `40002` 和当前进度，完成后返回转写内容。
3. 打开播放器，确认聊天面板出现文字，点击文字能跳到对应时间。
4. 故意把推理服务停掉，再访问转写接口，确认任务显示「转写引擎不可用」，重新启动推理服务后下次访问自动恢复。

## 八、常见问题排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 连接超时或拒绝 | 服务只监听了 `127.0.0.1`；防火墙未放行；IP 或端口写错 | 改为监听 `0.0.0.0`；放行端口；用 `curl` 逐步验证 |
| 返回 `502`，但服务明明在运行 | 本机配置了 HTTP 代理，内网请求被代理拦截 | 把 GPU 机器地址加入 `NO_PROXY` |
| 返回 `401` | token 不对或没带 | 检查请求头 `Authorization: Bearer ...` 和两侧的 token 是否一致 |
| 返回 `413` | 文件超过服务或反向代理的大小限制 | 调大限制（nginx 的 `client_max_body_size`），或上传 FLAC |
| 一直返回 `503` | 模型仍在加载，首次使用需下载模型 | 看 `/health` 的 `models` 字段，等待加载完成；查看 GPU 机器日志 |
| 返回 `429` | 队列满 | 等待 `Retry-After` 后重试；必要时调大队列或限制主后端并发 |
| 进度长时间不动 | 前面有任务在排队；GPU 显存溢出；某阶段卡住 | 看 `stage` 和 `/health` 的 `queue`；查 GPU 机器日志和显存 |
| 文字和声音对不上，整体偏移 | 段内时间没有加回该段的起点偏移 | 检查推理服务的时间换算，参照联调第 5 步 |
| 时间戳超出音频时长 | 同上，或对齐结果未截断 | 在推理服务里把时间限制在 `[0, duration]` |
| 英文录音说话人分得不准 | CAM++ 官方模型偏中文 | 先只用声道区分说话人；英文效果需单独评估 |
| 出现对方说的话（幽灵文字） | 麦克风串音 | 启用主后端的串音过滤（5.4） |
| 重启后任务重复推理 | 没有按 `sha256` 去重 | 提交时带上 `sha256`；服务端命中后返回已有任务 |

## 九、安全与合规

- 通话录音属于敏感数据。推理服务只对内网开放，不要暴露到公网。
- 用 Bearer token 鉴权；跨网络（经过 VPN 或公网）时使用 HTTPS。
- 音频在任务结束后立即删除；日志里不输出音频内容和转写文本。
- 声纹属于**生物特征数据**，存储和访问要按公司合规要求控制；如果暂时不做跨通话识别，可以先只做声道内的说话人标注，不保存声纹向量。
- 录音是否允许传到另一台电脑，需要先确认合规要求。

## 十、落地顺序

1. 推理服务的接口定义（本文第四章）评审确定。
2. 写一个**假的推理服务**，返回固定结果，用来跑通主后端的 `RemoteAsrProvider` 和测试，不依赖真实模型。
3. GPU 机器上实现推理服务：先 VAD、ASR、对齐，保证句级时间戳准确。
4. 实测并接入串音过滤，用 `audio_003` 验证。
5. 加入情感和声音事件。
6. 加入声纹，先做声道内说话人标注，再视合规情况做跨通话识别。

## 附录：模型分工

| 模型 | 作用 |
|---|---|
| Qwen3-ASR-1.7B | 主转写模型：文本、语种 |
| ForcedAligner | 强制对齐：生成句级时间戳 start / end |
| FSMN-VAD | 长音频语音活动检测分段，也是说话人按段标注的基础 |
| CAM++ | 说话人特征：匿名说话人标注 + 192 维声纹 embedding |
| SenseVoiceSmall | 情感、音频事件、语种标签（按输入段） |

**资源参考：** Qwen3-ASR-1.7B 加 ForcedAligner 大约 8–10GB 显存，建议使用 GPU，CPU 上 21 分钟的双路音频会很慢；VAD、CAM++、SenseVoice 体积都很小。依赖包括 `torch`、`funasr`、`modelscope` 和 Qwen3-ASR 对应的包，要先确认与运行环境（Python 版本）兼容。
