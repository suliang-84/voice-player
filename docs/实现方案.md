# voice_ai 实现说明

本文说明 voice_ai 的**运行架构、模块设计、请求生命周期、数据流转和关键取舍**，目标是让读者不读完全部源码也能理解系统如何工作。

> 接口参数、响应字段、错误码和 curl 示例以 [API.md](API.md) 为唯一权威文档；前端字段契约以 [interface.md](interface.md) 为准。本文只解释实现。
>
> 离线打包与内网部署见 [OFFLINE_DEPLOY.md](OFFLINE_DEPLOY.md)。

适用代码：`fronted-use` 分支，服务版本 `0.1.0`。

---

## 1. 系统概览

### 1.1 能力边界

当前服务把三类能力放在同一个进程、同一个端口（默认 `10090`）中：

| 能力 | 入口 | 核心实现 |
|---|---|---|
| 语音转写、时间戳、匿名说话人、语种、情感、音频事件 | `/api/v1/transcribe`、`/api/v1/analyze`、`/api/v1/asr` 等 | `FunasrPipeline` |
| 静音检测、波形 peaks、音频截取、左右声道提取 | `/api/v1/silence/*`、`/api/v1/peaks`、`/api/v1/trim`、`/api/v1/channels/*` | `services/silence.py` 等 + ffmpeg/soundfile |
| 声纹注册、1:N 识别、1:1 验证 | `/api/v1/speakers/*` | `SpeakerEmbedder` + `SpeakerDB` |
| 前端契约适配（envelope、`audioId` 资源） | `/api/v1/audios/*`、`/api/v1/speakers` 等 | `app/frontend/` |

明确的边界：

- 只处理**文件级**音频，不支持流式 ASR。
- 音频和转写结果**不落库**；唯一持久化数据是 PostgreSQL 中的声纹表。
- 模型在进程启动时加载一次，运行中不热切换。
- 单进程、单 worker；`WORKERS` 不是 1 时配置层直接拒绝启动。
- 前端契约中的设置、鉴权、翻译、转写编辑等仍是演示数据，见第 5.5 节。

### 1.2 运行时拓扑

```text
Client / Frontend
        │  HTTP multipart / query file_id / query url / WebSocket
        ▼
┌──────────────────────────────────────────────────────────────────┐
│ uvicorn + FastAPI（单进程、单 worker）                           │
│ app/main.py：lifespan、全局异常、/、/health、路由注册            │
└───────────────┬──────────────────────────────────────────────────┘
                │ include_router
    ┌───────────┼───────────────────────────┬───────────────────────┐
    ▼           ▼                           ▼                       ▼
api/asr.py   api/audio.py             api/speakers.py        frontend/router.py
转写/分析     静音/peaks/截取/声道       声纹注册/识别/验证      契约 envelope + audioId
    │           │                           │                       │
    └───────────┴──────────────┬────────────┴───────────┬───────────┘
                               ▼                        ▼
                         api/deps.py              frontend/mapping.py
                   workdir / 输入解析 / WAV / 锁    纯映射函数
                               │
        ┌──────────────────────┼─────────────────────────┐
        ▼                      ▼                         ▼
 FunasrPipeline          audio services             SpeakerDB
 Qwen3-ASR + VAD         soundfile/numpy/ffmpeg     PostgreSQL
 + Aligner + CAM++       （CPU、流式读写）           （声纹表）
 + SenseVoice
        ▲
        └── SpeakerEmbedder 复用 pipeline 内的 CAM++，不重复加载
```

进程内共享资源都挂在 `app.state` 上：

| 资源 | 创建位置 | 使用方 |
|---|---|---|
| `pipeline` | `lifespan` | ASR、分析、契约转写、场景 |
| `speaker_embedder` | `lifespan`，复用 `pipeline` | 声纹接口、契约说话人 |
| `speaker_db` / `speaker_db_ready` | `lifespan` | 声纹接口、契约说话人 |
| `inference_lock` | `lifespan` | 所有 GPU 推理 |

进程外依赖：

- **PostgreSQL**：只存声纹；不可用时核心转写仍可用。
- **`FILE_BASE_URL` 指向的音频静态服务**：`file_id` 和契约 `audioId` 的下载源；可指向内网对象存储或静态文件服务。
- **ffmpeg / ffprobe**：非 WAV 输入转码依赖；截取、声道、静音、peaks 本身用 soundfile，但输入需先成为可读 WAV。conda 环境内自带。

单机部署时这三者与 FastAPI 进程同机或同网段即可；离线内网的实际拓扑和安装步骤见 [OFFLINE_DEPLOY.md](OFFLINE_DEPLOY.md)。

### 1.3 设计原则

1. **模型只加载一次**：Qwen3-ASR、VAD、ForcedAligner、CAM++、SenseVoice 都只保留一份；声纹提取复用 ASR pipeline 里的 CAM++。
2. **GPU 串行、IO 并行**：GPU 推理统一经过 `inference_lock`；ffmpeg、soundfile/numpy、数据库、ZIP、上传落盘放到线程池，避免阻塞事件循环。
3. **请求级临时目录**：每个请求创建 `TEMP_DIR/req_*`，音频、转码结果和截取结果都放在里面，结束后删除；不跨请求复用。
4. **核心服务与协议适配分离**：`services/` 不依赖 FastAPI；`api/` 负责 HTTP 校验和响应模型；`frontend/` 只负责 envelope 和字段映射。
5. **可降级启动**：模型或数据库初始化失败不阻止进程启动，而是让 `/health` 报告 `degraded`，让相关接口返回 503。

### 2.3 依赖方向

```text
main.py
  ├── api/*.py ────────────▶ api/deps.py ───────────▶ services/*
  ├── frontend/router.py ──▶ api/deps.py / services/* / api/speakers.register_speaker
  └── services/* ──────────▶ config / errors / schemas
```

约定：

- `services/` 不导入 FastAPI 路由，保持可被脚本或其他入口复用。
- `api/` 负责 HTTP 语义（查询参数、状态码、响应模型），不实现音频算法。
- `frontend/` 是协议适配层，不复制算法；唯一跨层复用是调用 `api/speakers.register_speaker` 的注册核心，避免重复实现 ID/时长/声纹校验。
- `mapping.py`、`fakes.py` 是无副作用函数，便于单独测试。

## 3. 启动与生命周期

`app/main.py` 的 `lifespan` 按顺序执行：

1. `settings.ensure_dirs()`：创建上传、临时、日志目录。
2. `setup_logging(settings)`：控制台 + `LOG_DIR/voice_ai.log`，并把 uvicorn 日志接入 root logger。
3. 初始化 `app.state`：`inference_lock`、`pipeline=None`、`speaker_embedder=None`、`speaker_db`、`speaker_db_ready=False`。
4. `FunasrPipeline(settings)`：
   - 检查 ASR、ForcedAligner、VAD、CAM++、SenseVoice 目录是否存在；
   - 通过 FunASR `AutoModel` 加载 Qwen3-ASR，并把对齐、VAD、CAM++ 作为子模型；
   - 单独加载 SenseVoice；
   - 失败时只记录异常，进程继续启动。
5. 若 pipeline 成功，创建 `SpeakerEmbedder`，复用 pipeline 内的 CAM++。
6. `SpeakerDB.init_schema()`：建 `speakers` 表、索引，并补 `role` 列；失败时 `speaker_db_ready=False`。
7. 开始接收请求；关闭时记录 `voice_ai stopped`。

失败降级行为：

| 失败项 | 结果 |
|---|---|
| 模型加载失败 | `/health` 为 `degraded`；ASR/分析/契约转写等返回 503；纯音频处理仍可用 |
| PostgreSQL 不可用 | ASR/音频接口正常；声纹接口和契约说话人返回 503 / `50001`；`/health` 显示 `database_ready=false` |
| ffmpeg 不可用 | 非 WAV 输入无法转码，返回 503；已是可读 WAV 的部分功能仍可用；`/health` 为 `degraded` |
| 全部正常 | `/health` 为 `ok`，包含 `asr`、`sensevoice`、`speaker`、`ffmpeg` 四个组件状态 |

`/health` 的 `ok` 条件是 **pipeline 已加载 + 数据库已初始化 + ffmpeg 可找到**；这三个条件分别对应 ASR、声纹和媒体处理。

## 4. 请求处理模型与并发

### 4.1 一次请求的生命周期

```text
HTTP request
   │
   │ 1. 路由层校验：FastAPI 参数 / 契约层手工解析
   ▼
new_workdir()                      TEMP_DIR/req_xxxxxxxx
   │
   │ 2. resolve_input()
   │    ├── file    ：1 MiB 分块写入 workdir/upload_*.<suffix>
   │    ├── file_id ：FILE_BASE_URL/{file_id} 下载到 workdir/source_*
   │    └── url     ：逐跳校验后下载到 workdir/source_*
   ▼
ensure_wav()
   │    ├── 已是可读 WAV 且采样率/声道满足要求：直接使用原文件
   │    └── 否则 ffmpeg 转为 PCM16 WAV：workdir/audio.wav
   ▼
业务处理
   ├── GPU：run_locked(...)         线程池中执行 + inference_lock
   ├── CPU/IO：run_in_threadpool(...)  ffmpeg、soundfile、numpy、DB、ZIP
   └── 网络：async httpx             file_id / url 下载
   ▼
响应
   ├── JSON：Pydantic 模型 / envelope
   └── 文件：FileResponse + X-* 元数据头
   ▼
清理 workdir
   ├── JSON 响应：finally 中 cleanup_workdir()
   └── 文件响应：BackgroundTask(cleanup_dir)，响应发送完成后删除
```

每个请求的 workdir 通过 `tempfile.mkdtemp(prefix="req_", dir=TEMP_DIR)` 创建，因此并发请求不会共享文件。

### 4.2 线程与资源边界

| 工作 | 执行位置 | 原因 |
|---|---|---|
| 路由编排、参数校验、响应组装 | 事件循环 | 快速、非阻塞 |
| `file_id` / `url` 下载 | 事件循环 + `httpx.AsyncClient` | 网络等待异步化；每 1 MiB 检查大小并写盘 |
| 上传文件落盘 | 线程池 | `UploadFile` 读取和磁盘写入可能阻塞 |
| ffmpeg/ffprobe | 线程池 | 子进程可能运行数秒 |
| soundfile/numpy（静音、peaks、截取、声道） | 线程池 | CPU/IO 密集，避免卡住事件循环 |
| ZIP 打包 | 线程池 | 压缩 CPU/IO 密集 |
| PostgreSQL 操作 | 线程池 | psycopg 同步连接，避免阻塞事件循环 |
| GPU 推理 | 线程池 + `inference_lock` | 单卡显存有限，所有推理串行 |
| workdir 清理 | 线程池 / BackgroundTask | `rmtree` 可能阻塞 |

`run_locked` 的实现要点：

```python
def _run():
    with lock:
        return fn(*args, **kwargs)

return run_in_threadpool(_run)
```

锁在 **worker 线程内**获取，所以排队请求不会阻塞事件循环；但每个排队请求仍占用一个线程池线程。并发极高时，线程池可能被等待 GPU 的请求占满，影响其他线程池任务。生产环境应限制同时处理数，而不是依赖队列无限堆积。

### 4.3 不跨请求缓存

同一份音频的多个请求会各自：

1. 下载/上传；
2. 转码（如果不是可读 WAV）；
3. 推理或计算。

这是业务决策：音频通常只处理一次并入库保存，重复请求少；缓存会引入失效、磁盘增长和多租户隔离问题。因此当前没有 `audioId` 结果缓存，也没有转写/peaks 缓存。

## 5. 数据流

### 5.1 统一输入与 WAV 转换

所有处理接口都支持三种输入，且必须**三选一**：

| 输入 | 落盘位置 | 校验与限制 |
|---|---|---|
| multipart `file` | `workdir/upload_<8hex><suffix>` | 1 MiB 分块；`MAX_UPLOAD_BYTES`；空文件拒绝；后缀只保留最后一段且长度 ≤ 12 |
| query `file_id` | `workdir/source_<8hex><suffix>` | `FILE_BASE_URL/{id}`；拒绝空段、`.`、`..`；404→404；非 2xx→502；超时→502；`MAX_DOWNLOAD_BYTES` |
| query `url` | `workdir/source_<8hex><suffix>` | 仅 `http/https`；拒绝内嵌凭据；长度 ≤ 4096；每一跳都做 DNS/私网校验；默认拒绝非全局地址；最多 `URL_FETCH_MAX_REDIRECTS` 跳；大小/超时同上 |

`file_id` 与直连 URL 的区别：

- `file_id` 的根地址来自 `FILE_BASE_URL`，是受信任的配置，下载时使用 `follow_redirects=True`，不逐跳做 SSRF 校验。
- 直连 `url` 来自调用方，必须逐跳校验；`URL_FETCH_ALLOW_PRIVATE=false` 时拒绝回环、私网、链路本地和保留地址，防止 SSRF。
- 直连 URL 的 DNS 校验与实际连接之间存在 DNS rebinding 窗口；严格场景应由出站代理/网关白名单兜底。

WAV 快速路径（`services/convert.py`）：

1. 读取前 12 字节，识别 `RIFF` / `RF64` / `BW64` + `WAVE`；
2. 用 `libsndfile` 尝试 `sf.info()`，确认可解析；
3. 如果调用方没有强制采样率/声道，或现有布局已满足要求，直接复用原文件；
4. 否则调用 ffmpeg：`-vn -sn -dn`，可选 `-ar`/`-ac`，输出 `pcm_s16le`。

因此：

- ASR/音频处理默认**保留**原始采样率和声道；
- 声纹输入强制 **16 kHz 单声道**（CAM++ 的要求）；
- 已经是合适 WAV 的文件不会多一次 ffmpeg 转码。

### 5.2 ASR 与分析

```text
api/asr.py
  → new_workdir()
  → resolve_wav()
  → run_locked()
      → FunasrPipeline.transcribe() / analyze()
          → Qwen3-ASR.generate()
              ├── FSMN-VAD 分段
              ├── ForcedAligner 句级时间戳
              └── CAM++ 段级说话人 embedding + 聚类
          → 语种（Qwen3-ASR）
          → 若请求 emotion/events 且语种受支持：
                SenseVoice.generate() → 解析 <|lang|><|emotion|><|event|> 标签
          → 组装结果
  → Pydantic 响应 / 清理 workdir
```

`FunasrPipeline` 的核心方法：

| 方法 | 作用 | 返回 |
|---|---|---|
| `transcribe_asr(path, mode)` | 只跑 Qwen3-ASR 分支 | `{text, sentences, language}`；句子时间戳为毫秒，`spk` 为匿名编号或 `None` |
| `transcribe(path, mode)` | ASR + 条件 SenseVoice | 增加 `emotion`、`audio_events` |
| `analyze(path, tasks, mode)` | 按任务组合，结果在请求内共享 | `{asr?, timestamps?, language?, emotion?, events?}` |
| `embed_speaker(path)` | 复用 CAM++ 提特征并 L2 归一化 | 192 维 `list[float]` |
| `transcribe_sensevoice(path)` | 单独跑 SenseVoice 并解析标签 | `{language, emotion, audio_events, text, raw}` |

任务矩阵：

| `tasks` | 是否跑 Qwen3-ASR | 是否跑 SenseVoice | 结果键 |
|---|---|---|---|
| `asr` | 是 | 否 | `asr.text`、`asr.language` |
| `timestamps` | 是 | 否 | `timestamps.sentences` |
| `language` | 是 | 否 | `language` |
| `emotion` | 是（先定语种） | 语种受支持时 | `emotion.label`、`emotion.language` |
| `events` | 是（先定语种） | 语种受支持时 | `events`（标签列表） |

说明：

- `analyze` 会去重并保留调用方顺序；空 `tasks` 默认 `asr`；未知任务返回 400。
- 只请求 `emotion`/`events` 时也必须先跑 Qwen3-ASR，因为 SenseVoice 的语种标签只在五种语言内可靠。
- `/transcribe` 固定返回 ASR + SenseVoice 的组合结果；`/asr` 等价于 `analyze(["asr","timestamps","language"])`；`/emotion`、`/events`、`/language` 分别调用对应的单任务组合。
- `/analyze` 的 `timings_ms.total` 从进入 `run_locked` 前开始计时，包含排队等待 GPU 锁的时间，不包含下载、上传和转码。

#### 两种 mode

| mode | 行为 | `sentences` |
|---|---|---|
| `speech`（默认） | VAD 分段 + 对齐 + CAM++ 说话人 | 多句，含 `start/end`（毫秒）和 `spk` |
| `whole` | 绕过 VAD、对齐、说话人，直接调用 Qwen3-ASR 内嵌模型的 `transcribe` | 单句 `0..duration`，`spk=null` |

`whole` 适合歌曲、带 BGM 或不需要分句的音频；即使 `whole`，请求 `emotion/events` 时 SenseVoice 仍会运行。

#### 语种与 SenseVoice 过滤

- 语种以 Qwen3-ASR 为主；`_to_iso_lang` 把模型返回的英文语言名（如 `English`）映射为 ISO 代码（`en`）。
- SenseVoice 只支持 `zh`、`en`、`yue`、`ja`、`ko`。其他语种直接返回 `emotion=unknown`、`audio_events=[]`（或空 `events`）。
- Qwen3-ASR 语种为 `unknown` 时，允许 SenseVoice 兜底提供语种。
- `parse_sensevoice` 会移除 `<|...|>` 控制标签，剩余文本作为显示文本；事件列表可能包含 `Speech`，但契约层的 `build_scenes` 会跳过 `Speech`。

### 5.3 音频处理

| 接口 | 服务 | 算法 | 输出 / 内存特征 |
|---|---|---|---|
| `POST /api/v1/silence/detect` | `detect_silence` | 帧级 RMS → dBFS；低于 `noise_db` 为静音；合并连续帧；过滤短于 `min_silence_duration` 的段 | JSON；多声道先下混为单声道；约 10 秒一块读取 |
| `POST /api/v1/peaks` | `compute_peaks` | 每声道分成 `points` 个桶，取每桶 min/max | JSON；每次读取约 16 MB float32；尾部不足一桶的样本忽略 |
| `POST /api/v1/trim` | `trim_audio` | 截取 `[start,end)`，默认到文件尾；保留采样率/声道；输出 PCM16 | WAV 文件；1,048,576 帧一块流式读写；元数据放 `X-*` 响应头 |
| `POST /api/v1/channels/extract` | `extract_channels` | 左/右声道分别写单声道 PCM16；单声道源只有 left；`both` 打 ZIP | WAV/ZIP；1,048,576 帧一块流式读写 |

细节：

- 静音检测默认帧长 `SILENCE_FRAME_MS=10`，块大小按约 10 秒对齐到帧；末尾不足一帧会零填充，和整文件读取的边界行为一致。
- `peaks` 的桶大小为 `max(1, frames // points)`；`points` 会被限制在帧数以内。
- `trim` 和 `channels` 的起止时间会对采样点范围做钳制；`end <= start` 返回 400。
- 单声道源请求 `channel=right` 返回 400；`channel=both` 返回只含 `left.wav` 的 ZIP，并通过 `X-Warnings` 说明。
- ffmpeg/ffprobe 的超时映射为 422；二进制缺失或不可执行映射为 503；错误详情只保留 stderr 尾部，避免超大日志进入响应。

### 5.4 声纹

#### 注册

```text
POST /api/v1/speakers/register
  → 校验 speaker_id（1–64 位字母/数字/_ . -）、name（≤128）、role（≤32）
  → workdir + resolve_wav(speaker_input=True)  // 16 kHz 单声道
  → duration >= SPEAKER_MIN_DURATION_SECONDS（默认 1.0s）
  → run_locked(embedder.embed)                  // CAM++ + L2 归一化
  → SpeakerDB.upsert()
  → SpeakerRegisterResponse(created=...)
```

- `speaker_id` 省略时自动生成 UUID hex；重复 ID 覆盖旧声纹，`created=false`。
- role 是可选元数据；重复注册未传 role 时保留旧值（SQL `COALESCE`）。
- 太短的音频在 GPU 推理前拒绝，避免不稳定 embedding 污染声纹库。

#### 1:N 识别

```text
POST /api/v1/speakers/identify
  → resolve_wav(16 kHz mono) → CAM++ embedding
  → SpeakerDB.identify()
      ├── SQL 先按 embedding_dim 过滤
      ├── 取出向量做 NumPy 矩阵点积（已 L2 归一化，等价余弦相似度）
      ├── 排序取 top_k（1–50）
      └── 最高分 >= threshold 才算 identified / best_match
  → 返回 identified、threshold、best_match、matches
```

`matches` 返回 Top-K 候选，即使低于阈值也会出现在列表里；`best_match` 只在最高分达到阈值时非空。

#### 1:1 验证

```text
POST /api/v1/speakers/verify?speaker_id=...
  → embedding
  → SpeakerDB.verify()
      ├── 未知 speaker_id：matched=false，score=0.0（不是 404）
      ├── 维度不一致：DatabaseError（503）
      └── 否则 dot(query, stored) >= threshold
```

声纹数据模型、备份和敏感数据说明见第 6 节与 [DATABASE.md](DATABASE.md)。

### 5.5 前端契约适配层

契约接口不改变核心服务，只在服务之上做三件事：下载 `audioId`、把内部结果转成前端字段、把业务错误包成 HTTP 200 + envelope。除 `/ws` 外，本节路径都带 `/api/v1` 前缀。

```text
GET /api/v1/audios/{audioId}/...
  → contract_endpoint 包装
  → fetch_audio(audioId)
      ├── 未配置 FILE_BASE_URL → ContractError(50001)
      ├── validate_file_id(audioId)
      ├── FILE_BASE_URL/{audioId} 下载到 workdir
      └── ensure_wav()（保留原始采样率/声道）
  → 调用对应服务：
      peaks      → compute_peaks
      silences   → detect_silence_channels（按声道单遍）
      transcripts→ pipeline.transcribe_asr("speech")
      speakers   → extract_channels + CAM++ + SpeakerDB.identify
      scenes     → pipeline.analyze(["events"])
  → mapping.py 转换字段
  → ok(data) 或 fail(code)
  → 清理 workdir
```

`audioId` 就是远端 `file_id`：服务端不保存音频；每个契约请求都会重新下载。`FILE_BASE_URL` 是受信任配置，因此这里使用普通下载（允许重定向），不做直连 URL 的逐跳 SSRF 校验。

#### envelope 与业务码

所有契约接口对**已知业务错误**返回 HTTP 200：

```json
{"code": 0, "message": "success", "data": {}, "timestamp": 1760000000000}
```

| 异常 | envelope `code` |
|---|---|
| 正常 | `0` |
| 参数错误（400） | `400` |
| 音频不存在（404） | `40001` |
| 文件过大（413） | `40004` |
| 处理失败（MediaError / 422） | `50002` |
| 上游、数据库、模型/服务不可用 | `50001` |

未预期异常不包装，仍走全局 HTTP 500（`{"detail": "Internal server error."}`）。`timestamp` 是毫秒时间戳；业务数据里的 `generatedAt` 是 UTC ISO 字符串。

#### 契约接口与数据来源

| 接口 | 实现程度 | 数据来源 / 缺失字段 |
|---|---|---|
| `GET /audios/{id}/peaks` | 真实 | `compute_peaks`；A=左、B=右；每桶 min/max 折叠为“绝对值最大且保留符号”的单值，按 `precision` 取整；`peaks` 外层固定为单元素数组 |
| `GET /audios/{id}/silences` | 真实 | `detect_silence_channels` 单遍按声道计算；`threshold`（RMS）转 dBFS；单声道只有 A 轨 |
| `GET /audios/{id}/transcripts` | 真实 | Qwen3-ASR `speech` 模式；`spk` 索引映射为 `trackId`；时间毫秒转秒；`confidence=null`；ID 由 `sha1(audioId:index)` 确定性生成 |
| `GET /audios/{id}/speakers` | 部分真实 | 拆 A/B 轨→16 kHz 单声道→CAM++→1:N；命中回填 `identity`/`confidence`/`role`；逐说话人情感、意图为 `null` |
| `GET /audios/{id}/scenes` | 部分真实 | SenseVoice 事件映射为 `scenes[]`；`confidence=null`；呼叫语义字段为 `unknown`/`null` |
| `POST /api/v1/speakers` | 真实 | 表单上传注册 CAM++ 声纹，可带 `role`；复用 `register_speaker` |
| `GET/PUT /users/settings` | 演示 | 固定默认值；PUT 浅合并回显，不落库 |
| `POST /auth/refresh` | 演示 | 固定 demo token |
| `GET /audios/{id}/translations`、`PUT /translations/{id}` | 演示 | 固定两条译文；编辑仅回显 |
| `PUT /transcripts/{id}/text` | 演示 | 不持久化，回显文本和时间 |
| `WS /ws` | 占位 | 接受连接并保持，不推送任务事件 |

#### 字段映射规则

| 内部值 | 契约值 | 规则 |
|---|---|---|
| `spk=0/1/2...` | `trackId=A/B/C...` | `chr(ord("A") + spk)`；`spk=None` → `A` |
| 句子 `start/end`（毫秒） | `startTime/endTime`（秒） | 除以 1000，保留 3 位 |
| 语言 `zh/en/yue/ja/ko` | BCP-47 风格标签 | `zh-CN`/`en-US`/`yue`/`ja-JP`/`ko-KR`；其他原样 |
| peaks 每桶 min/max | 单个带符号值 | 取绝对值更大的 min 或 max，再按 `precision` 取整 |
| 静音 `threshold`（RMS） | dBFS | `20*log10(max(threshold, 1e-12))` |
| SenseVoice 事件 | `scenes[]` | 跳过 `Speech`，去重；映射 `type/subType/description/keywords` |
| 注册 role | 说话人 role | 优先用声纹库中的 role；否则 A=`agent`、B=`customer` |

#### 注册 → 识别 → role 回填

1. `POST /api/v1/speakers` 上传单人音频，提取 CAM++ 向量写入 PostgreSQL，可标注 `role`。
2. `GET /audios/{id}/speakers` 拆出 A/B 轨，各自提取向量并在声纹库做 1:N。
3. 命中：`identity`=注册 name、`confidence`=余弦分；注册时带 role 则回填，否则按轨道约定。
4. 未命中：`identity`/`confidence` 为 `null`，role 走轨道约定。
5. 重复注册同一 `speakerId` 且不传 role 时保留原值；声纹库不可用返回 `50001`。

## 6. 持久化与数据状态

### 6.1 唯一持久化表

服务启动时自动创建：

```sql
CREATE TABLE IF NOT EXISTS speakers (
    speaker_id      TEXT PRIMARY KEY,
    name            TEXT NOT NULL,
    role            TEXT,
    embedding       DOUBLE PRECISION[] NOT NULL,
    embedding_dim   INTEGER NOT NULL,
    model_name      TEXT NOT NULL,
    model_version   TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS speakers_created_at_idx ON speakers (created_at);
-- 旧库升级：ALTER TABLE speakers ADD COLUMN IF NOT EXISTS role TEXT;
```

### 6.2 写入与匹配

- 每个 `speaker_id` 只保留一条当前 embedding，重复注册覆盖。
- 写入使用单条 `INSERT ... ON CONFLICT ... RETURNING (xmax = 0)`，一次往返完成 upsert 并正确返回 `created`。
- role 在冲突路径用 `COALESCE(EXCLUDED.role, speakers.role)`，避免未传 role 时被清空。
- embedding 入库前 L2 归一化，因此余弦相似度 = 点积。
- 1:N 先按 `embedding_dim` 过滤，再用 NumPy 矩阵乘法批量打分；适合中小规模库，大规模需要 pgvector/HNSW。
- 每个数据库操作新建连接，没有连接池；这是当前简单实现的取舍，高 QPS 场景需要补池化。
- 没有多段注册、质量门禁、自动阈值校准、pgvector 索引。

### 6.3 非持久化数据

- 上传/下载的音频、转码 WAV、截取 WAV、声道 WAV、ZIP 都在请求 workdir 中，请求结束即删除。
- 转写、时间戳、情感、事件、peaks、静音结果都不写入数据库。
- 前端的设置、鉴权、翻译、转写/翻译编辑均为固定演示数据或回显，不落库。
- 需要通话级查询、历史转写、重复来电识别时，必须新增通话/转写/分析结果表。

声纹属于敏感生物特征；数据库和备份应加密、限制访问、保留审计和删除策略，详见 [DATABASE.md](DATABASE.md) 与 [OFFLINE_DEPLOY.md](OFFLINE_DEPLOY.md)。

## 8. 可观测性与错误处理

### 8.1 日志

- 控制台 + `LOG_DIR/voice_ai.log`，按 `LOG_MAX_BYTES` 轮转，保留 `LOG_BACKUP_COUNT` 份。
- uvicorn 的 access/error 日志清空自有 handler，统一走 root logger，避免重复输出。
- 重新初始化日志时会关闭旧 handler，避免测试/重载时泄漏文件描述符。

### 8.2 错误映射

`errors.py` 定义统一异常：

| 异常 | 默认 HTTP | 语义 |
|---|---|---|
| `InputError` | 400 | 调用方参数不合法 |
| `NotFoundError` | 404 | 远端文件/声纹不存在 |
| `MediaError` / `FFmpegError` | 422 | 转码或音频处理失败 |
| `UpstreamError` | 502 | 远端文件源失败/超时 |
| `DatabaseError` | 503 | PostgreSQL 操作失败 |
| `ServiceUnavailableError` | 503 | 模型、二进制或数据库不可用 |

- `/api/v1/*` 由全局 handler 返回 `{"detail": ..., "error": ...}`；`error` 仅在底层原因有价值时出现。
- 请求参数校验错误统一为 422，`detail` 固定为 `Invalid request parameters.`，`error` 携带字段详情。
- 未捕获异常记录完整 traceback，客户端只收到通用 500。
- 契约接口由 `contract_endpoint` 捕获 `ContractError`/`AppError`，转换为第 5.5 节的 envelope；未预期异常仍走 HTTP 500。
- 文件响应（截取、声道）无法携带 JSON，错误仍使用 HTTP 状态码和 `detail`。

### 8.3 健康检查

`/health` 返回：

{
  "status": "ok",
  "version": "0.1.0",

## 9. 性能与容量特征

### 9.1 已做的优化

| 优化 | 效果 |
|---|---|
| 模型进程内单例 | 启动后所有请求共享，无重复加载/显存占用 |
| CAM++ 复用 | 声纹接口不再加载第二份 CAM++ |
| GPU 锁在 worker 线程内获取 | 排队请求不阻塞事件循环 |
| ffmpeg、上传、清理、DB、ZIP 下线程池 | 避免长任务卡住其他请求 |
| 静音/peaks 分块读取 | 内存不随音频长度线性增长 |
| 截取/声道流式读写 | 长音频不整文件载入内存 |
| 契约静音按声道单遍计算 | 省去临时声道 WAV 和二次读取 |
| WAV 快速路径 | 已是合适 WAV 时跳过 ffmpeg |
| 声纹 SQL 单条 upsert + NumPy 点积 | 减少数据库往返和 Python 循环 |
| 契约层只保留一份原始 WAV | 不再生成未使用的 16 kHz 副本 |

开发机实测（0.6B，非正式基准）：

| 场景 | 结果 |
|---|---|
| 7.176 秒英文音频 `/analyze` | 约 1.04 秒（ASR + SenseVoice） |
| 10 分钟 mp3 转码期间 `/health` 最大延迟 | 647 ms → 9.9 ms（IO 下线程池后） |
| 10 分钟立体声声道提取 | 峰值内存增量 330 MB → 20 MB；耗时约 420 ms → 331 ms |
| 10 分钟整段截取 | 峰值内存增量约 20 MB |

### 9.2 容量约束

- **单 GPU、单 worker**：推理串行，吞吐由单卡决定；并发请求排队。
- **等待 GPU 的请求占线程池线程**：极端并发会挤占其他线程池任务；生产应限制同时处理数或加队列。
- **8 GB 显存**：1.7B + SenseVoice + 对齐同时驻留偏紧；建议 12 GB 以上，或使用 0.6B 开发配置。
- **临时磁盘**：每个请求的音频、转码结果、截取/声道文件在 `TEMP_DIR`；需要按最大上传/下载量和并发数预留空间。
- **无缓存**：同一音频的重复请求会重复下载、转码和推理。
- **数据库每次新建连接**：高 QPS 下需要连接池或外部 PgBouncer。

模型体积与设备配置见第 10 节；启动方式见第 7 节；离线打包与内网部署见第 10.2 节和 [OFFLINE_DEPLOY.md](OFFLINE_DEPLOY.md)。

### 10.1 当前模型

所有模型在进程启动时加载一次并全程共享；体积为开发机实测值。

| 模型 | 路径 | 体积 | 作用 |
|---|---|---|---|
| Qwen3-ASR-0.6B | `/opt/qwen3/models/Qwen3-ASR-0.6B` | 1.8G | 开发机默认：文本、语种、配合对齐产出时间戳与 `spk` |
| Qwen3-ASR-1.7B | `/opt/qwen3/models/Qwen3-ASR-1.7B` | 4.4G | 同 0.6B，精度更高、显存更大；生产交付使用 |
| Qwen3-ForcedAligner-0.6B | `/opt/qwen3/models/Qwen3-ForcedAligner-0.6B` | 1.8G | 强制对齐，生成句级 `start/end` |
| FSMN-VAD | `/opt/qwen3/models/iic/speech_fsmn_vad_zh-cn-16k-common-pytorch` | 3.9M | 长音频语音活动检测分段，也是说话人按段标注的基础 |
| CAM++ | `/opt/qwen3/models/iic/speech_campplus_sv_zh-cn_16k-common` | 28M | 匿名说话人 embedding + 192 维声纹 |
| SenseVoiceSmall | `/opt/qwen3/models/iic/SenseVoiceSmall` | 897M | 情感、音频事件（整段级；仅 zh/en/yue/ja/ko） |

加载方式：

- `FunasrPipeline` 用 FunASR `AutoModel` 加载 Qwen3-ASR，并把 `forced_aligner`、`vad_model`、`spk_model` 作为子模型传入；`spk_mode="vad_segment"`。
- SenseVoice 单独一个 `AutoModel`，设备由 `SENSEVOICE_DEVICE` 控制。
- 有意不加载 FunASR 标点模型：Qwen3-ASR 已输出带标点文本。说话人分支仍会打印 `Missing punc_model, which is required by spk_model.`，这是预期日志，不代表请求失败。
- `ASR_DEVICE` 覆盖 Qwen3-ASR、VAD、对齐和 CAM++；`SENSEVOICE_DEVICE` 独立覆盖 SenseVoice；统一 `ASR_DTYPE=float16`。
- `whole` 模式直接调用 Qwen3-ASR 内嵌模型，绕过 VAD/对齐/说话人。

## 11. 已知限制

- 情感/事件是**整段标签**，不是逐句；没有置信度；SenseVoice 仅支持 `zh`/`en`/`yue`/`ja`/`ko`，其他语种返回 `unknown`/空列表。
- `spk=0/1` 是录音内匿名编号，不等于跨录音身份；同一人可能被分成多个编号。
- 单轨混音在抢话、笑声、音乐段分离不稳定；双人对话优先使用双轨录音。
- 说话人分支会打印 `Missing punc_model...`；Qwen3-ASR 已带标点，不额外加载 FunASR 标点模型，请求仍正常。
- 当前只有 `speakers` 表，没有通话、转写、分析结果的持久化模型。
- `language` 复用 Qwen3-ASR，识别语种时会跑 ASR；`emotion`/`events` 也先由 ASR 定语种。
- 直连 URL 在 DNS 校验与连接之间存在 rebinding 窗口；严格场景需要出站代理/白名单。
- `file_id` 和契约 `audioId` 的下载信任 `FILE_BASE_URL`，不逐跳做 SSRF 校验；该配置必须指向可信服务。
- 声纹阈值 `0.5` 未按业务校准；CAM++ 为中文通用模型，跨语种/跨域需验证。
- 单进程单 worker；高并发下 GPU 推理串行，等待请求占用线程池线程。
- 1.7B + SenseVoice 同时驻留对 8 GB 显存偏紧，测试默认 0.6B。
- 不支持流式、KWS、防伪、降噪、翻译；前端契约中的设置/鉴权/翻译/编辑仍是演示数据。
- 契约层不做跨请求缓存；同一 `audioId` 的多接口调用会重复下载和推理。
- 契约 `scenes` 只有整段事件聚合，没有时间点；呼叫语义字段无法从音频标签推断。
- 契约 `track` 查询参数只接受 `A`/`B`，而内部 `speaker_track` 可映射到 `C+`；超过两人的结果只能在 `both` 模式返回，不能单独按 `C+` 过滤。
- 旧接口（`local_path`、`/transcribe/path`、`/api/upload`）已删除，不提供兼容。

## 12. 后续演进

以下排序按“复用现有基础件的成本”和“业务价值”给出，不是承诺排期。

### P0：双人对话分析

可复用：句级时间戳、匿名说话人、双轨拆分、静音检测、CAM++、SenseVoice 整段标签。

| 能力 | 需要的改动 |
|---|---|
| 双轨角色化转写 + SRT/VTT | 双轨直接映射坐席/客户；单轨用 `spk`；字幕携带角色 |
| 对话行为指标 | 双方时长/占比、话轮数、平均话轮时长、最长独白、响应延迟 P50/P90、抢话、冷场、语速 |
| 逐句情感/事件时间线 | 对每个 VAD 段调用 SenseVoice；情绪转折用规则先行 |
| 声纹确认与检索 | 坐席身份确认、客户注册、目标说话人检索；重复来电需要通话级持久化 |
| 质检与脱敏 | 关键词/禁语、开场结束语、手机号/证件号脱敏、削波/响度/双轨串音 |
| 语义层 | 摘要、意图、场景、解决方案、合规质检需要 LLM；翻译需要 MT/LLM |

前置建议：优先双轨录音；新增通话/转写/分析表；CAM++ 余弦分不是概率；SenseVoice 只有离散标签，没有校准置信度。

### P1：声纹与情感增强

- 多段注册、注册质量门禁（VAD 裁剪、SNR、静音比例、多人检测）。
- 阈值校准工具（ROC/EER），按业务选择阈值。
- pgvector/HNSW 索引，支持大规模 1:N。
- 防伪/活体检测、声纹加密、审计、删除接口、用户授权。
- 逐句事件时间范围、更细粒度事件模型、情绪分数校准（需要标注数据）。

### P2：其它语音能力与工程化

- KWS、热词、性别/年龄、降噪/增强、目标说话人提取、语音翻译、流式 ASR/VAD。
- 鉴权、限流、请求审计；Prometheus/GPU 指标；任务队列/多卡调度。
- 数据库连接池、更完整的 pytest 集成测试。
- 已落地：离线 conda-pack 打包、前端契约适配层、流式音频处理、请求级临时目录。
