本文说明**当前代码**的整体架构、前后端设计、关键流程、与模型的对接方式，以及各模型的能力。目标是让读者不读完全部源码，也能理解系统怎么工作、哪些是真实实现、哪些还是 mock、接真实模型要改哪里。

> - 接口参数、响应字段、错误码：以 [接口设计说明书.md](接口设计说明书.md) 为准（唯一权威）。

## 一、系统概览

### 1.1 做什么

通话 / 对话录音的双轨（A 路、B 路）播放器：波形展示、A/B 同步播放、跳过空音、混声 / 立体声播放、按路或合并下载、选区截取，以及转写、说话人身份、场景分析、翻译。

### 1.2 组成与架构

```
┌────────────────────────── 浏览器 ───────────────────────────┐
│  voice-player-frontend（Vue 3 + Vite + WaveSurfer.js 7）     │
│  App.vue → VoicePlayer.vue ← composables/useAudioData.js     │
│                          ↘ api/（axios、WebSocket、鉴权）      │
└───────────────┬───────────────────────────┬─────────────────┘
        HTTP /api/v1（含音频流、下载）      WebSocket /ws（事件推送）
┌───────────────▼───────────────────────────▼─────────────────┐
│  voice-player-backend（FastAPI，单进程）                      │
│  routers：audios · content · account · ws                    │
│  services：storage · audio · *_cache · ingest                │
│            pipeline（线程池）· hub（WS 广播）                  │
│            asr（AsrProvider）· llm（LlmClient）· mock          │
│  SQLite（任务、转写、翻译、分析、用户设置）                      │
│  data/audios（音频）  data/cache（派生文件）                    │
└───────────────┬───────────────────────────┬─────────────────┘
        转写引擎（可替换）                    大模型（OpenAI 兼容，可替换）
   mock ｜ faster-whisper ｜ 目标：本机模型 Worker            mock ｜ 真实接口
```

### 1.3 技术栈

| 层 | 技术 |

| 后端 | Python（开发环境 3.13）、FastAPI、SQLAlchemy 2（默认 SQLite）、pydantic-settings、soundfile + numpy（音频分块处理）、httpx、PyJWT、ffmpeg（非 WAV 转码） |
| 转写 | 可替换：`mock`（默认）、`faster-whisper`、`none`；目标是本机的 5 个模型（第七章） |
| 大模型 | OpenAI 兼容的 `/chat/completions`（身份推断、场景分析、翻译），或 `mock` |

### 1.5 关键约定

- JSON 字段 camelCase；统一信封 `{code, message, data, timestamp}`；HTTP 状态码如实返回（转写未完成的 `40002` 返回 200）。
- **A 轨 = 左声道，B 轨 = 右声道**；单声道文件只有 A 轨；超过 2 声道只处理前两个。时间一律是秒（浮点），以整条音频开头为 0。
- `audioId` 匹配 `^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$`，同时是 `data/audios/` 里的文件名。

### 2.2 数据层

- **`api/`**：`request.js`（axios，`VITE_API_BASE`，自动拆信封、`ApiError`、令牌刷新）、`index.js`（接口函数与 `streamUrl`、`downloadUrl`）、`auth.js`（`configureAuth` 注入令牌）、`ws.js`（WebSocket，断线指数退避重连，未配 `VITE_WS_URL` 则不连）、`peaks.js`（适配后端的峰值格式）。
- **`composables/useAudioData.js`**：按 `audioId` 拉取并持有播放器要用的全部后端数据。
  - 波形数据（先于 WaveSurfer 创建）：`peaks`、联合静音区间 `skipRanges` 与有声区间 `activeRanges`。
  - 转写类数据（音频就绪后再加载，不阻塞播放）：转写、译文、说话人、场景；转写与译文按 `transcriptId` 合并成气泡条目。
  - 转写未完成时：WebSocket 推送进度和完成事件；没有 WebSocket 时每 5 秒轮询。
  - 每个请求返回时检查 `audioId` 是否已变，丢弃过期结果。
- **用户设置**（倍速、步长、播放模式、跳过空音、立体声、主题、聊天面板）：启动时 `GET /users/settings`，修改后防抖 300ms `PUT`（合并语义）。
- **本地存储**：书签、批注存 `localStorage`（以音频地址为 key）。

### 2.3 核心机制

**波形与播放。** 每一路创建一个原生 `<audio>`（`crossOrigin='anonymous'`，边缓冲边播放）交给 WaveSurfer，并传入后端预计算的 `peaks` 与 `duration`，WaveSurfer 不再下载解码整条音频。峰值与音频时长相差超过 1 秒时放弃峰值，回退为浏览器解码。

**双轨同步。** A、B 同时 `play / setTime`；两路时长不同时，把较短一路的峰值补零到较长一路的时长（以最大时长为统一时间基准），点击波形按统一基准换算 seek 位置；放大后 `requestAnimationFrame` 同步两路滚动位置，底部有一条统一滚动条。

**切换音频。** `audioId` 变化时销毁旧播放器，重新拉取数据后重建 A、B 两路；用递增的切换序号丢弃过期的切换，连点「下一条」不会交叉；创建前先销毁同一路残留的实例。

**跳过空音。** 区间由后端算好（见 3.4），前端只做两件事：
1. 播放时，由主轨的 `timeupdate`（WaveSurfer 播放中逐帧触发）判断当前时间是否落在某个联合静音区间内，是则把 A、B 两路一起 seek 到区间末尾。
2. 在波形上用浅色底加底边线标出**有声**部分（画在 WaveSurfer 内部 wrapper 中，随缩放、滚动移动，位置按占总时长的百分比，行内样式）。开关关闭时标记消失；状态存入用户设置。

**混声 / 立体声。** 混声：两路原生播放，各自居中。立体声：经 WebAudio，`createMediaElementSource → StereoPanner`，A 路 pan=-1、B 路 pan=+1。只有开启过立体声才创建 `AudioContext`，并在用户点击、播放时 `resume`，避开浏览器自动播放限制。

**下载。** 有 `audioId` 且没有用 `src` / `file` 覆盖时，一律交给后端 `GET /audios/{id}/download`，浏览器直接导航下载，文件名由后端给出：单路用 `track=A|B`；顶部下载按当前模式用 `track=mix`（混声）或 `track=stereo`（立体声）；选区下载带 `start`、`end`。传入外部 `src` / `file` 时退回浏览器本地处理。

**选区与书签。** 拖拽波形创建选区（A、B 同步），选区上有浮动工具条；可循环播放；双击波形添加书签。

**转写面板。** 气泡按时间排列，当前播放位置的气泡高亮并自动滚动，双击跳转到该句，右键可编辑转写或译文（`PUT /transcripts/{id}/text`、`PUT /translations/{id}`）；轨道头部显示说话人身份「（疑似…）」；场景对话框展示场景、通话目的、结果和分析标记。

### 3.2 配置

环境变量与 `.env`，完整列表见 [后端 README](../voice-player-backend/README.md#配置env完整示例见-envexample)。要点：

- 默认 `ASR_PROVIDER=mock`、`LLM_PROVIDER=mock`，不需要任何模型即可跑通。
- 音频入口：`UPLOAD_ENABLED`（开发测试用）、`INGEST_ALLOWED_HOSTS`（入库地址白名单，为空则不接受任何地址）。
- 静音：`SILENCE_*`，默认阈值自适应；转写：`WHISPER_*`、`ASR_LOAD_TIMEOUT`、`ASR_RETRY_INTERVAL`；大模型：`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 等。

### 3.3 存储与缓存

- 音频：`DATA_DIR/audios/{audioId}.<ext>`。后端不关心音频原本存在哪里，入库接口把它拉到这里；找不到时音频相关接口返回 `40001`。
- 非 WAV（mp3、m4a 等）：`storage.source_wav` 用 ffmpeg 转成 PCM WAV 缓存到 `data/cache/{audioId}/source.wav`。
- 声道文件：`track_A.wav`、`track_B.wav`（`extract_channel` 从立体声里拆出），供播放、转写、下载使用。
- 峰值、静音：`peaks_{N}.json`、`silences_{哈希}.json`；派生文件都按源文件修改时间判断是否过期，删掉即可重算。
- 重新入库（`force=true`）会删除该音频的文件、缓存和数据库里的转写、翻译、分析、任务记录。

### 3.4 音频处理算法（`services/audio.py`）

全部分块读取（约 10 秒一块），内存不随音频长度增长。

- **峰值：** 每个轨道按桶取绝对值最大的采样（保留符号），默认 8000 点。
- **逐帧 RMS：** 每 10ms 一帧，每个声道各一条曲线。
- **联合静音（`detect_silences`）：**
  1. RMS 先做 150ms 滑动平滑，抹掉数十毫秒的小杂音。
  2. 每个声道各自算**自适应阈值**：取「底噪（第 10 百分位）+ 12dB」与「语音电平（第 90 百分位）− 20dB」中较大者，限制在 -65～-35 dBFS。
  3. 一帧在 **A、B 两路都低于各自阈值**才算静音（单声道只看 A）。
  4. 夹在静音之间、短于 0.3 秒的有声段并入静音；短于 `minDuration`（默认 1 秒）的静音丢弃。
  5. 保留下来的静音区间两端各缩进 0.15 秒（文件开头、结尾的一侧不缩），作为**可跳过区间**，避免跳转切掉词头词尾。
  6. `activeSegments` 是 `[0, 时长]` 去掉可跳过区间的补集，前端用来在波形上标出有声部分。
  - `/silences` 同时返回每路单独的静音（`tracks`）和联合结果（`both`）；参数 `threshold`（固定阈值）、`minDuration`、`speechOffsetDb`（灵敏度）可覆盖默认值。
- **下载（`render_wav`）：** 按模式写 PCM16 WAV——`A`/`B` 取单个声道；`mix` 两路平均成单声道；`stereo` A 左 B 右；`start`/`end` 只含该时间范围。整条单路直接用声道缓存，其余渲染到临时文件，响应结束后删除。

### 3.5 数据模型（SQLite，`models.py`）

| 表 | 内容 |
|---|---|
| `tasks` | 每个音频一条转写任务：`audio_id`（主键）、`task_id`、`status`（processing / completed / failed）、`progress`、`language`、`error` |
| `transcripts` | 转写片段：`id`、`audio_id`、`track_id`（A/B）、`start_time`、`end_time`、`text`、`confidence` |
| `translations` | 译文：对应 `transcript_id`，含 `language`、时间、文本 |
| `analyses` | 大模型分析结果：主键（`audio_id`, `kind`），`kind` 为 `speakers` 或 `scenes`，`data` 为 JSON |
| `user_settings` | 按用户保存的设置（JSON） |

建表用 `create_all`，**不会给已存在的表加列**，改表结构要自己迁移（真实模型接入需要新增字段，见模型对接方案第十章）。

### 3.6 任务流水线（`services/pipeline.py`）

- 一个 2 线程的线程池执行后台任务；`_inflight` 防止同一音频重复提交。
- **触发：** 上传或入库成功后 `on_uploaded`（提交峰值预计算 + 转写）；首次访问转写、译文、说话人、场景接口时 `ensure_transcription`（没有任务就创建）。
- **转写任务（`_run`）：**
  1. 引擎不可用（未安装、模型加载中或失败）时任务置为 `failed`，错误信息带前缀「转写引擎不可用：」；引擎恢复后下次访问**自动重试**。
  2. 取声道列表，逐声道调用 `asr.transcribe(声道文件, on_progress)`，进度映射到 0～85%。
  3. 两路片段按开始时间合并、写入 `transcripts`（先清旧结果），进度 90%。
  4. 配置了大模型且有转写内容时：`_analyze`（身份、场景，写 `analyses`）→ `_translate`（默认语种预翻译）。大模型失败只让对应部分退回默认值，不影响转写。
  5. 任务置为 `completed`，写入主导语种，推送完成事件。
- **进度与事件：** `_progress` 写库并推送 `transcription_progress`；峰值生成后推送 `peaks_generated`；完成推送 `transcription_completed`。
- **其它：** 服务重启时 `resume_unfinished` 重新提交状态仍为 `processing` 的任务；`reset` 在重新入库时清掉该音频的所有结果（正在处理的拒绝）。

### 3.7 实时推送

`Hub` 在进程内保存 WebSocket 连接；工作线程调用 `publish`，通过 `run_coroutine_threadsafe` 回到事件循环广播。**因此后端必须单进程运行**。`/ws?token=` 在启用鉴权时校验令牌。

### 3.8 鉴权与错误

- `AUTH_ENABLED=true` 时校验 HS256 JWT（令牌由业务系统签发，后端不提供登录）；`<audio>` 与下载无法带 `Authorization` 头，`/stream`、`/download` 支持 `?token=`；`/auth/refresh` 支持刷新令牌或（可已过期的）访问令牌。关闭时所有请求视为同一匿名用户。
- 业务码：`40001` 音频不存在（404）、`40002` 转写未完成（200）、`40003` 格式不支持（415）、`40004` 文件过大（413）、`50001` 服务暂不可用（503）、`50002` 文件处理失败（422）；另有 400、401、403、404、409、500 等。统一信封，异常统一转成信封。

## 四、关键流程

### 4.1 打开页面与播放

```
App.vue 取 playlist[current].audioId
  → VoicePlayer 挂载：加载用户设置
  → useAudioData.loadAll：GET /peaks、GET /silences（联合区间）            ← 波形数据先于播放器创建
  → 为 A、B 各建 <audio>（src = /stream?track=A|B）+ WaveSurfer（传入 peaks）
  → 播放器就绪后 loadDetails：GET /transcripts、/translations、/speakers、/scenes
        └─ 转写未完成：40002 + 进度 → WebSocket 推送（或每 5 秒轮询）→ 完成后重新加载
```

### 4.2 音频入库

```
入库系统（音频已在非结构化库中）
  → POST /api/v1/audios/{audioId}/ingest  { source: { type: "url", url } , force }
        校验地址在白名单内（只允许 http/https，不跟随重定向）
        已入库且未 force → 直接返回 alreadyIngested（幂等）
        流式下载到 data/audios/{audioId}.<ext>（先写临时文件再改名；超限返回 413）
        解析音频信息（必要时 ffmpeg 转码）；失败则清掉
        → on_uploaded：预计算峰值 + 创建转写任务
```

`force=true` 时先下载成功，再清旧数据并替换，下载失败不会丢掉已有的音频和转写。

### 4.3 转写（当前 mock，目标真实模型）

```
任务启动 → 拆出 A、B 声道 WAV → 逐声道 transcribe → 合并写库 → 大模型分析 + 翻译 → completed
```

- **mock**：按音频真实的说话时段切句（所以高亮和波形对得上），句子文字是虚构的「遥控器设计会议」；大模型部分返回固定的身份、场景，翻译查表。
- **真实模型**：见第七章；流程骨架不变，替换 `transcribe` 的实现，并按两段式输出（先文字、后补说话人和情感）。

### 4.4 跳过空音

后端：`/silences` → 联合静音区间（3.4）。前端：播放时命中区间就把两路一起跳到区间末尾，并在波形上标出有声部分（2.3）。

### 4.5 混声 / 立体声与下载

- 播放：开关决定 A、B 是居中（混声）还是 A 左 B 右（立体声）。
- 下载：单路按钮 → `track=A|B`；顶部按钮 → 混声用 `mix`、立体声用 `stereo`；选区按钮 → 该路加 `start`、`end`。

### 4.6 重新入库与清理

`/ingest` 的 `force=true` 会清掉该音频的转写、翻译、分析和任务记录。**不要只删 `tasks` 表里的记录**：重新转写只重建转写表，旧的翻译行（按 `audio_id` 查询）会残留，和新译文一起返回。

## 六、与模型的对接方式

系统里有两类模型，对接方式都是「接口 + 配置开关 + 失败降级」。

### 6.1 两类模型

| 类别 | 作用 | 对接接口 | 配置 |
|---|---|---|---|
| **语音模型**（转写引擎） | 把语音转成带时间的文字 | `AsrProvider.transcribe(path, on_progress) -> (语种, [Segment])`，`path` 是单声道 WAV | `ASR_PROVIDER` |
| **大语言模型** | 根据转写文字推断说话人身份、场景，并做翻译 | `LlmClient.analyze(dialogue, track_ids)`、`translate(items, language)` | `LLM_PROVIDER`，或 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` |

### 6.2 转写引擎（`services/asr.py`）

- `Segment(start, end, text, confidence)`，时间以整条音频开头为 0。
- 可选属性 `state`（`idle/loading/ready/failed`）、`error`、`start_preload()`、`wait_ready(timeout)`：流水线据此判断引擎是否就绪；抛出 `AsrUnavailable` 会让任务显示「转写引擎不可用」，恢复后自动重试。
- `build_provider()` 按 `ASR_PROVIDER` 选择：

| 取值 | 实现 | 说明 |
|---|---|---|
| `mock`（默认） | `MockAsrProvider` | 不加载模型，随时就绪，进度按 `MOCK_DELAY` 模拟 |
| `faster-whisper` | `FasterWhisperProvider` | 每个声道独立转写（`vad_filter=True`），置信度取 `exp(avg_logprob)`；后台预加载模型。**开发机上报错**：`open() got an unexpected keyword argument 'metadata_errors'`（疑为依赖版本不匹配，未排查） |
| `none` | — | 不启用，任务失败并提示 |

### 6.3 大语言模型（`services/llm.py`）

- `LlmClient` 向 `LLM_BASE_URL/chat/completions` 发请求（温度 0.2，要求只输出 JSON），本地推理服务（Ollama、vLLM 等的 OpenAI 兼容接口）可直接用；调用失败抛 `LlmError`，只会让身份、场景、翻译退回默认值。
- 转写文字拼成 `[轨道 mm:ss] 内容` 逐行的对话（最多 `LLM_MAX_CHARS` 个字符）交给模型，A、B 各代表一位说话人。
- 输出经 `normalize_analysis` 收敛为接口约定的结构：缺失或越界的字段用安全默认值；`role` 只取 `agent` / `customer`；置信度限制在 0～1，情感得分在 -1～1。
- `LLM_PROVIDER=mock` 时用 `MockLlm`（固定数据），优先于真实配置。

### 6.4 目标：本机的五个模型

音频放在本机时，模型放进**独立的本机 Worker 进程**（独立环境，监听 `127.0.0.1`），主后端新增 `LocalWorkerProvider`，通过 HTTP 提交任务、轮询进度、取结果；`Pipeline` 的任务、进度、失败重试、事件推送都复用。要点：

- **传路径不传文件**，一个任务带 A、B 两路，按**阶段优先**处理，大模型同一时刻只驻留一个，ASR 默认常驻（速度优先）。
- **两段式输出**：文字阶段先交出并写库，对齐、说话人、情感等作为补充阶段后补；补充完成后推送 `transcription_enriched`，前端据此重新加载。
- 转写表、任务表新增字段，新增声纹表，并补一段轻量迁移（`create_all` 不会加列）。

完整设计（接口、内存调度、数据库、测试、落地顺序）见 [本机模型对接实现方案.md](本机模型对接实现方案.md)。

### 6.5 降级与失败处理

| 情况 | 处理 |
|---|---|
| 转写引擎未安装、模型加载中、Worker 连不上 | 任务 `failed`，提示「转写引擎不可用：…」，引擎恢复后下次访问自动重试 |
| 大模型未配置或调用失败 | 身份 `unknown`、场景为空、译文为空；转写结果不受影响 |
| 补充阶段（对齐、说话人、情感）某一步失败 | 只缺对应字段，文字照常返回 |
| 其它转写异常 | 任务 `failed` 并保留错误信息；这类失败**不会**自动重试（需 `force` 重新入库） |

## 七、大模型能力

### 7.1 语音模型（目标接入）

以下是各模型在本系统里的作用。**具体的接口、参数、单段长度上限、语种覆盖都没有对照官方模型卡核实**，落地前需确认。

| 模型 | 能力 | 在系统中的作用 | 注意 |
|---|---|---|---|
| **Qwen3-ASR-1.7B** | 语音转文字、语种识别 | 主转写模型：逐语音段转写，得到文本和语种 | 1.7B 参数，CPU 上很可能慢于实时；阿拉伯语等是否支持需核实 |
| **ForcedAligner** | 强制对齐（文本与音频对齐） | 把转写文字对齐回音频，得到字/词级时间，再合成句级 `start`/`end` | 对哪些语种可用需核实；失败的句子退回 VAD 段边界 |
| **FSMN-VAD** | 长音频语音活动检测 | 切出语音段；只让语音段进转写模型；也是说话人按段标注的基础；可用于升级跳过空音 | 很小，可常驻 |
| **CAM++** | 说话人特征 | 192 维声纹；声道内聚类做匿名说话人标注（`spk0`、`spk1`）；第一阶段声纹只存不用 | 常用官方模型偏中文，英文有单独的模型，多语种效果需实测；声纹是生物特征数据，需合规 |
| **SenseVoiceSmall** | 情感、声音事件、语种标签 | 每段的情感和声音事件（咳嗽、笑声、呼吸）；汇总成说话人的情绪分布和情感得分；事件可用于过滤杂音 | 据我所知只覆盖中、粤、英、日、韩，**不含阿拉伯语**，这类片段不输出情感 |

### 7.2 大语言模型

| 能力 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 说话人身份推断 | 带轨道标记的对话文本 | 每个说话人的 `identity`（自由描述，如「某运营商客服人员」）、`confidence`、`role`（agent / customer）、`emotionDistribution`、`sentimentScore`、`dominantIntent` | 只能依据文本线索，不得编造姓名或公司名；线索不足填 `unknown`；`confidence` 是模型自评，未校准 |
| 场景分析 | 同上 | `scenes`（类型、子类型、置信度、描述、关键词）、通话类型、目的、结果、分析标记（投诉、表扬、升级） | 按置信度从高到低排序 |
| 翻译 | 一批 `{id, text}` 与目标语言 | `{id: 译文}` | 保持含义与语气，不增删；条目数量和 id 必须一致；默认语种在转写后预翻译，其它语种按需翻译 |

真实模型接入后，说话人的情绪分布和情感得分改由 SenseVoice 汇总覆盖，大模型只负责身份、场景、意图和翻译。

### 7.3 能力 × 状态

| 能力 | 当前（mock 默认） | `faster-whisper` + 真实大模型 | 目标（本机五个模型） |
|---|---|---|---|
| 转写文字 | 虚构文字；**时间点按真实说话时段** | 真实文字，段级时间；开发机上报错 | Qwen3-ASR，句级时间由对齐给出 |
| 语种识别 | 固定 `en-US` | 自动识别 | 自动识别，按片段记录 |
| 语音活动检测 | 无（静音用能量法） | 转写内部带 VAD | FSMN-VAD |
| 说话人 | 声道即说话人（A/B） | 同左 | 声道内再用 CAM++ 聚类 |
| 说话人身份、场景 | 固定内容 | 大模型推断（未做过真实调用验证） | 同左 |
| 翻译 | 查表（中文有内置译文） | 大模型 | 同左 |
| 情感、声音事件 | 无（情绪分布来自固定数据） | 仅大模型的粗略推断 | SenseVoice |
| 声纹 | 无 | 无 | CAM++（只存不用） |
| 串音过滤 | 无 | 无 | 流水线层按两路音量对比 |

### 7.4 语种

录音以英文为主，也有汉语、阿拉伯语、日语、韩语。转写不指定语种、自动识别，按片段记录；各阶段对不支持的语种按「省略字段、退回上一级结果」降级（不输出情感、对齐退回 VAD 边界、说话人只按声道区分），详见模型对接方案第四章。

## 八、部署与运维

- **运行：** 后端 `python -m app`（默认 10090），前端 `npm run dev`（5173，开发代理 `/api`、`/ws` 到后端）；生产构建 `npm run build`。**后端必须单进程**（任务调度与 WebSocket 广播都在进程内）。
- **数据：** `DATA_DIR` 下的 `audios/`、`cache/`、`voice_player.db`；`data/` 不入 git。演示音频随仓库放在 `demo/`，用 `scripts/seed_demo.py` 复制进去。
- **依赖：** 非 WAV 音频需要 ffmpeg；真实转写引擎需要额外安装（`requirements-asr.txt`）。
- **健康检查：** `GET /health` 返回引擎状态（`asrState`：`loading/ready/failed/unavailable`）和大模型是否启用。
- **安全：** 入库地址白名单、只允许 http/https、不跟随重定向；`AUTH_ENABLED=true` 时必须设置 `JWT_SECRET`；音频不按用户隔离（契约未定义归属）。

## 九、测试

后端 `pytest`，73 个用例，测试里用假引擎和假大模型，**不调用真实模型**。覆盖：音频上传与入库、峰值、静音（含联合静音）、下载（单路、混声、立体声、选区）、转写任务与进度、翻译与编辑、大模型解析、用户设置与鉴权、并发、mock 转写与 mock 大模型的端到端。前端没有自动化测试。

## 十、已知限制与后续

- **转写、身份、场景、翻译是 mock**，真实模型未接入；说话人分离、情感、声纹、串音过滤都没有做。
- **前端的混声 / 立体声开关、三种下载、波形上的有声标记**：接口已用真实音频验证，前端只做了构建，没有完整的浏览器点测。
- 跳过空音的参数只在 `audio_003` 上调过；更轻的附和声可能被当成静音跳过。
- 数据库没有迁移机制；音频不按用户隔离；峰值与静音超过 2 声道只处理前两个。
- `audio_003` 是会议录音，麦克风互相串音；开发机没有 GPU，本地大模型的速度和内存需要在目标机器上实测。
- 前端 `scripts/mock-server.js` 已落后于接口，不可用。
