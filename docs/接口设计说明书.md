# 音声播放器前端项目 - 后端接口设计规范

## 一、统一返回体格式定义

### 1.1 通用响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "timestamp": 1729600000000
}
```

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| code | Number | 业务状态码：`0` 成功；非 `0` 为业务错误码（见 1.3、8.1），与 HTTP 状态码相互独立 |
| message | String | 可直接展示给用户的提示文案；成功时通常为 `success` |
| data | Object/Array/null | 实际响应数据；无返回内容或错误时可为 `null` |
| timestamp | Number | 服务端生成响应时的 Unix 时间戳（毫秒），用于客户端排序、日志排查和时序校验 |

### 1.2 分页响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 100,
    "page": 1,
    "pageSize": 20,
    "totalPages": 5
  },
  "timestamp": 1729600000000
}
```

`data` 内字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| items | Array | 当前页的记录列表；元素结构由具体接口定义 |
| total | Number | 符合条件的记录总数（不是当前页条数） |
| page | Number | 当前页码，从 `1` 开始 |
| pageSize | Number | 每页条数 |
| totalPages | Number | 总页数，通常为 `ceil(total / pageSize)`；`total=0` 时为 `0` |

### 1.3 错误响应格式

```json
{
  "code": 400,
  "message": "参数验证失败",
  "data": null,
  "timestamp": 1729600000000
}
```

说明：

- 错误时 `data` 通常为 `null`；若错误可附带上下文（如任务进度），`data` 为对象，结构见 8.2。
- HTTP 状态码与 `code` 相互独立：HTTP 表示传输/协议层结果，`code` 表示业务结果，客户端应优先判断 `code`。

**常用错误码：**

| 错误码 | 含义 |
|--------|------|
| 0 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 404 | 资源不存在 |
| 500 | 服务端错误 |
| 503 | 服务不可用 |

### 1.4 字段命名与单位约定

| 约定项 | 说明 |
|--------|------|
| 字段命名 | JSON 字段统一使用 camelCase，例如 `startTime`、`totalSilenceDuration` |
| 时间点/时长 | 除特别注明外，均以**秒**为单位，允许小数（如 `1.25`）；`timestamp` 是**毫秒** |
| 日期时间 | `generatedAt`、`updatedAt` 等为 ISO 8601 字符串，建议统一使用 UTC（如 `2024-10-21T10:35:00Z`） |
| 轨道标识 | `trackId`/`track` 取值 `A`、`B`；查询参数额外支持 `both` 表示两路 |
| 置信度/分数 | `confidence` 一般为 `0～1`，越大越可信；`sentimentScore` 为 `-1～1`（负向到正向） |
| 百分比 | 名称含 `percentage` 的字段为 `0～100` 的百分数，不是 `0～1` 小数 |
| 音频标识 | `audioId` 为后端生成的音频唯一标识，不是文件路径 |
| 枚举大小写 | 枚举值大小写敏感，客户端应按原值透传，不做自动大小写转换 |

## 二、波形数据接口

### 2.1 获取波形峰值数据

**接口路径：** `GET /api/v1/audios/{audioId}/peaks`

**功能描述：** 获取预计算的波形峰值数据，用于前端 WaveSurfer 渲染，避免客户端解码大文件

**性能说明：** 后端预计算并缓存，前端 zoom 时无需重新解码，性能提升约 1000 倍

**路径参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| audioId | String | 是 | 音频唯一标识，由音频上传/列表接口返回 |

**请求参数（Query）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| track | String | 否 | 轨道：`A`/`B` 只返回指定轨道，`both` 或省略时返回两路 |
| maxLength | Number | 否 | 每路峰值点数量上限，默认 `8000`；值越大波形越精细，响应体也越大 |
| precision | Number | 否 | 峰值保留的小数位数，默认 `2`；用于控制 JSON 体积，不改变波形形状 |

**返回体示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "duration": 145.5,
    "sampleRate": 16000,
    "tracks": {
      "A": {
        "peaks": [[0.0, 0.12, -0.35, 0.58, -0.62, 0.41, -0.18, 0.0, 0.0, 0.27, -0.44, 0.71, -0.66, 0.38, -0.09, 0.0]],
        "duration": 145.5,
        "pointCount": 16
      },
      "B": {
        "peaks": [[0.0, 0.0, 0.0, 0.22, -0.31, 0.55, -0.49, 0.36, -0.52, 0.64, -0.28, 0.15, 0.0, 0.0, 0.07, 0.0]],
        "duration": 145.5,
        "pointCount": 16
      }
    },
    "generatedAt": "2024-10-21T10:35:00Z"
  },
  "timestamp": 1729600000000
}
```

`data` 字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| duration | Number | 音频总时长（秒） |
| sampleRate | Number | 音频采样率（Hz），如 `16000` |
| tracks | Object | 轨道数据对象，键为 `A`、`B`；请求指定 `track` 时只包含对应键 |
| tracks.{A/B}.peaks | Array<Array<Number>> | 波形峰值二维数组：**外层为声道，内层为按时间排列的峰值点**。每个轨道固定只返回 1 个声道，即 `[[...]]`；内层长度必须等于 `pointCount`。详见下方「peaks 数据约定」 |
| tracks.{A/B}.duration | Number | 该轨道时长（秒），双轨正常录制时与顶层 `duration` 相同 |
| tracks.{A/B}.pointCount | Number | 该轨道实际返回的峰值点数量，可能小于 `maxLength` |
| generatedAt | String | 峰值数据生成时间（ISO 8601，UTC），可用于判断缓存是否过期 |

**peaks 数据约定：**

| 项 | 约定 |
|----|------|
| 结构 | `peaks` 外层是声道，内层是按时间排列的点；A、B 是两个独立轨道，每轨固定 1 个声道，即 `peaks: [[...]]` |
| 长度 | 内层长度必须等于 `pointCount`；示例为便于阅读仅给出 16 个点，实际最多 `maxLength`（默认 8000）个 |
| 取值 | 每个点取其时间段内**绝对值最大的采样值，保留正负号**，范围 `-1～1`；不使用 `[min, max]` 成对，也不使用 `[max[], min[]]` 两个数组 |
| 静音段 | 用 `0` 表示，不得省略 |
| 精度 | 由 `precision` 控制，默认保留 2 位小数 |
| 时间对应 | 每个点覆盖 `duration / pointCount` 秒；双轨的 `duration` 与 `pointCount` 应一致 |
| 归一化 | 后端无需归一化，前端渲染时自行处理 |
| 单轨请求 | 指定 `track=A` 或 `B` 时，`tracks` 只包含对应键 |

参考实现（numpy）：

```python
def make_peaks(samples, point_count, precision=2):
    # samples: 单声道 float32，范围 -1~1
    step = len(samples) / point_count
    out = []
    for i in range(point_count):
        seg = samples[int(i * step): int((i + 1) * step) or None]
        v = seg[np.argmax(np.abs(seg))] if len(seg) else 0.0   # 绝对值最大者，保留符号
        out.append(round(float(v), precision))
    return [out]   # 外层包一层 = 1 个声道
```

前端对非约定格式会尝试适配并在控制台输出 `[peaks]` 警告；无法识别时回退为浏览器解码，不影响播放，但会失去预计算带来的性能收益。

### 2.2 获取静音区间数据

**接口路径：** `GET /api/v1/audios/{audioId}/silences`

**功能描述：** 获取音频静音段信息，用于前端跳过空音功能

**路径参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| audioId | String | 是 | 音频唯一标识 |

**请求参数（Query）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| track | String | 否 | 轨道：`A`/`B` 只检测指定轨道，`both` 或省略时检测两路 |
| threshold | Number | 否 | 静音判定阈值（RMS 振幅，`0～1`）；值越大越容易判为静音。省略时每个声道自适应：取「底噪 + 12dB」与「语音电平 − `speechOffsetDb`」中较大者，限制在 -65～-35 dBFS |
| minDuration | Number | 否 | 最小静音时长（秒），默认 `1.0`；短于该值的间隙会被忽略 |
| speechOffsetDb | Number | 否 | 自适应阈值的灵敏度（`0～60`，dB），默认 `20`：比说话声低这么多的声音都当作背景。越小越容易判为静音，太小会把轻声的附和也跳掉；仅在省略 `threshold` 时有效 |

**返回体示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "tracks": {
      "A": {
        "silences": [
          { "start": 5.2, "end": 6.5, "duration": 1.3 },
          { "start": 15.8, "end": 18.2, "duration": 2.4 }
        ],
        "totalSilenceDuration": 45.3,
        "silencePercentage": 31.1
      },
      "B": {
        "silences": [
          { "start": 3.0, "end": 3.8, "duration": 0.8 }
        ],
        "totalSilenceDuration": 12.1,
        "silencePercentage": 8.3
      }
    },
    "both": {
      "silences": [
        { "start": 15.8, "end": 18.0, "duration": 2.2 }
      ],
      "activeSegments": [
        { "start": 0.0, "end": 15.8, "duration": 15.8 },
        { "start": 18.0, "end": 145.6, "duration": 127.6 }
      ],
      "totalSilenceDuration": 2.2,
      "silencePercentage": 1.5,
      "thresholdDb": { "A": -49.2, "B": -50.8 }
    },
    "generatedAt": "2024-10-21T10:35:00Z"
  },
  "timestamp": 1729600000000
}
```

`data` 字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| tracks | Object | 轨道静音结果，键为 `A`、`B`；请求指定 `track` 时只包含对应键 |
| both | Object | 两路联合静音，仅 `track=both`（或省略）时返回；单声道音频等同于只看 A 轨 |
| both.silences | Array<Object> | 可跳过区间：A、B 两路**同时**低于阈值的时间段，格式同 `silences` 元素 |
| both.activeSegments | Array<Object> | `silences` 的补集（`[0, 时长]` 去掉可跳过区间），即有声部分，用于在波形上标记 |
| both.thresholdDb | Object | 各声道实际使用的阈值（dBFS） |
| tracks.{A/B}.silences | Array<Object> | 该轨道的静音区间列表，按时间升序；无静音时为空数组 |
| tracks.{A/B}.totalSilenceDuration | Number | 该轨道静音总时长（秒） |
| tracks.{A/B}.silencePercentage | Number | 该轨道静音时长占比（百分数 `0～100`），不是 `0～1` |
| generatedAt | String | 检测结果生成时间（ISO 8601，UTC） |

联合静音（`both.silences`）的判定规则：逐帧（10ms）取 A、B 两路 RMS，先做 150ms 滑动平滑（抹掉小杂音），两路都低于各自阈值才算静音；夹在静音之间、短于 0.3 秒的零星有声帧（咳嗽、点击声）并入静音；短于 `minDuration` 的静音丢弃；保留下来的区间两端各缩进 0.15 秒（文件开头、结尾的一侧不缩），避免跳转时切掉词头词尾。

`silences` 数组元素说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| start | Number | 静音开始时间（秒），从音频开头计算 |
| end | Number | 静音结束时间（秒），必须大于 `start` |
| duration | Number | 静音时长（秒），等于 `end - start` |

### 2.3 下载音频

**接口路径：** `GET /api/v1/audios/{audioId}/download`

**功能描述：** 下载音频文件（WAV），支持单路、两路合并和按时间截取；合并与截取均在服务端完成。该接口为契约之外的辅助接口，响应是文件流而不是 JSON，由浏览器直接导航下载，鉴权 token 可通过 query 传递（同 `/stream`）。

**请求参数（Query）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| track | String | 否 | `A`（默认）/ `B`：单路；`mix`：两路平均混成单声道；`stereo`：立体声，A 在左声道、B 在右声道。单声道音频没有 B 轨，`mix`、`stereo` 得到单声道 |
| start | Number | 否 | 起始时间（秒），默认从头开始，必须小于音频时长 |
| end | Number | 否 | 结束时间（秒），默认到末尾，超出时长按时长截取；给出 `start` 时必须大于 `start` |

**返回：** `audio/wav`，`Content-Disposition: attachment`，文件名为 `{audioId}_{track}[_{start}-{end}s].wav`，例如 `audio_003_stereo.wav`、`audio_003_A_12.5-40.2s.wav`。参数错误时返回统一信封的 400。

前端按钮与参数的对应：单路下载 → `track=A|B`；顶部下载 → 当前为混声用 `track=mix`，立体声用 `track=stereo`；选区下载 → 该路的 `track` 加 `start`、`end`。

### 2.4 入库音频

**接口路径：** `POST /api/v1/audios/{audioId}/ingest`

**功能描述：** 入库系统完成音频入库后调用。后端按地址把音频拉到本地，并触发后台处理（峰值预计算、转写）。该接口为契约之外的辅助接口，鉴权方式与其他接口一致，只应对内网和入库系统开放。

**路径参数：** `audioId` 由调用方指定，需匹配 `^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$`（UUID、ObjectId 均符合）。

**请求体（JSON）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| source.type | String | 是 | 目前只支持 `url` |
| source.url | String | 是 | 音频下载地址（http/https），主机必须在 `INGEST_ALLOWED_HOSTS` 白名单内；可以是对象存储的预签名地址或入库系统的内部下载接口 |
| source.headers | Object | 否 | 下载时附带的请求头，如鉴权 |
| source.ext | String | 否 | 音频格式（如 `wav`、`mp3`）；地址没有后缀且对方没给 Content-Type 时使用 |
| force | Boolean | 否 | 默认 `false`。音频已入库时，`false` 直接返回已入库；`true` 在新文件下载成功后，删除旧音频及其转写、翻译、分析结果，以新文件为准重新处理 |

**返回体示例：**

```json
{
  "code": 0,
  "message": "音频入库成功",
  "data": {
    "audioId": "audio_001",
    "duration": 1272.64,
    "sampleRate": 16000,
    "channels": 2,
    "alreadyIngested": false
  },
  "timestamp": 1729600000000
}
```

`alreadyIngested` 为 `true` 表示该音频此前已入库，本次没有重新下载（`message` 为「音频已入库」）。

**错误：**

| HTTP 状态 | 说明 |
|-----------|------|
| 400 | 地址不是 http(s)、`audioId` 不合法、下载到的文件为空 |
| 403 | 地址主机不在白名单 |
| 409 | 该音频正在入库，或 `force=true` 时该音频正在处理 |
| 413 | 文件超过大小限制 |
| 415 | 无法确定音频格式 |
| 422 | 文件无法解析，格式不支持或已损坏 |
| 502 | 下载失败（连不上、对方返回非 200、超时）。`force=true` 时下载失败不会影响已有的音频和转写 |

说明：不跟随重定向，也不读取环境代理设置；转写在入库成功后自动开始，进度和结果通过现有的转写接口与 WebSocket 获取。

## 三、语音转写接口

### 3.1 获取转写内容

**接口路径：** `GET /api/v1/audios/{audioId}/transcripts`

**功能描述：** 获取音频转写内容列表，对应前端聊天面板展示

**路径参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| audioId | String | 是 | 音频唯一标识 |

**请求参数（Query）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| track | String | 否 | 轨道过滤：`A`/`B` 只返回该轨道，`both` 或省略时返回两路 |

**返回体示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "audioId": "audio_001",
    "status": "completed",
    "language": "zh-CN",
    "items": [
      {
        "id": "transcript_001",
        "trackId": "A",
        "startTime": 0.5,
        "endTime": 3.2,
        "text": "您好，请问是XX客服吗？",
        "confidence": 0.95
      },
      {
        "id": "transcript_002",
        "trackId": "B",
        "startTime": 3.8,
        "endTime": 6.1,
        "text": "您好，是的，请问有什么可以帮您？",
        "confidence": 0.94
      }
    ],
    "generatedAt": "2024-10-21T10:45:00Z"
  },
  "timestamp": 1729600000000
}
```

`data` 字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| audioId | String | 音频唯一标识，与路径参数一致 |
| status | String | 转写任务状态：`completed` 已完成、`processing` 处理中、`failed` 失败。未完成时 `items` 可能为空 |
| language | String | 识别出的源语种，使用 BCP 47 语言标签，如 `zh-CN`、`en-US` |
| items | Array<Object> | 转写片段列表，按 `startTime` 升序；每项对应聊天面板中的一条消息 |
| generatedAt | String | 转写结果生成时间（ISO 8601，UTC） |

`items` 数组元素说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 转写片段唯一标识，编辑接口 `/transcripts/{transcriptId}/text` 使用该值 |
| trackId | String | 来源轨道：`A` 或 `B`，用于区分双轨双方；单轨录音通常为 `A` |
| startTime | Number | 片段开始时间（秒），相对音频开头 |
| endTime | Number | 片段结束时间（秒），必须大于 `startTime` |
| text | String | 该片段的转写文本，已包含标点 |
| confidence | Number | 转写置信度（`0～1`），越高越可信；不同模型的分值不可直接横向比较 |

### 3.2 编辑转写内容

**接口路径：** `PUT /api/v1/transcripts/{transcriptId}/text`

**功能描述：** 修正单条转写文本内容（对应前端右键菜单「编辑转写内容」）

**路径参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| transcriptId | String | 是 | 要编辑的转写片段 ID，取自转写列表的 `items[].id` |

**请求参数（Body，`application/json`）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|

## 七、WebSocket 实时通知

### 7.1 建立连接

**地址：** `wss://api.example.com/ws?token=<auth_token>`

**功能描述：** 接收转写进度、波形生成等异步任务的实时推送

**连接参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| token | String | 是 | 登录后获取的访问令牌，与 HTTP 请求头 `Authorization: Bearer <token>` 使用同一份 |

说明：WebSocket 推送为事件对象，**不使用** 1.1 的统一响应体包装，`type` 字段即事件类型。

### 7.2 消息类型

**转写进度：**
```json
{
  "type": "transcription_progress",
  "taskId": "task_transcribe_001",
  "audioId": "audio_001",
  "progress": 45,
  "status": "processing"
}
```

**转写完成：**
```json
{
  "type": "transcription_completed",
  "taskId": "task_transcribe_001",
  "audioId": "audio_001",
  "status": "completed",
  "transcriptCount": 8
}
```

**波形生成完成：**
```json
{
  "type": "peaks_generated",
  "audioId": "audio_001",
  "taskId": "task_peak_001",
  "status": "completed"
}
```

**通用字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| type | String | 事件类型：`transcription_progress` 转写进度、`transcription_completed` 转写完成、`peaks_generated` 波形生成完成 |
| taskId | String | 异步任务唯一标识，与创建任务接口返回的任务 ID 对应，用于关联与去重 |
| audioId | String | 相关音频唯一标识 |
| status | String | 任务状态：`processing` 处理中、`completed` 已完成、`failed` 失败 |

**各事件附加字段：**

| 事件类型 | 字段 | 类型 | 说明 |
|----------|------|------|------|
| transcription_progress | progress | Number | 转写进度百分数（`0～100` 的整数，如 `45` 表示 45%） |
| transcription_completed | transcriptCount | Number | 本次生成的转写片段总数 |
| peaks_generated | - | - | 无附加字段；收到后调用波形接口拉取数据 |

说明：收到 `completed` 事件后，客户端应重新拉取对应的 REST 接口（转写/波形）以获取最终数据，事件本身不携带完整业务数据。

## 九、认证规范

### 9.1 请求头

```http
Authorization: Bearer <token>
Content-Type: application/json
X-Request-ID: <unique-request-id>
```

| 请求头 | 必填 | 说明 |
|--------|------|------|
| Authorization | 是（免登录接口除外） | `Bearer <token>` 格式，`<token>` 为登录/刷新接口返回的访问令牌 |
| Content-Type | 视正文类型 | 请求体为 JSON 时固定 `application/json`；GET 无正文时可省略 |
| X-Request-ID | 否 | 客户端生成的请求唯一标识（建议 UUID），便于前后端联调时用日志定位同一次请求 |

### 9.2 Token 刷新

**接口路径：** `POST /api/v1/auth/refresh`

**返回体示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "new_access_token",
    "refreshToken": "new_refresh_token",
    "expiresIn": 3600
  },
  "timestamp": 1729600000000
}
```

`data` 字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| token | String | 新的访问令牌；之后所有请求通过 `Authorization: Bearer <token>` 携带 |
| refreshToken | String | 新的刷新令牌；刷新成功后旧刷新令牌应视为失效 |
| expiresIn | Number | 访问令牌有效期（**秒**），如 `3600` 表示 1 小时；过期前建议提前刷新 |

说明：刷新令牌的传递方式（请求头或 Cookie）以及是否轮换由前后端另行约定；刷新失败（如令牌过期）返回 `401`（见 1.3），其余业务错误码见 8.1。
